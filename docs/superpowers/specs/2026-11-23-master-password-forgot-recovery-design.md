# マスターパスワード忘れ時の復旧設計

日付: 2026-11-23
方針: A。忘れ用の明示入口から二重確認で保護とAPIキーのみ削除する。

## 背景
現行の `removeMasterPassword` は旧パスか文脈保持のいずれかを要求する。忘れた場合は解除できず、設定も進めない。旧パスなしでの新規設定による維持は許可しない。その代わり、APIキーを削除して保護を無効化する復旧を用意する。

## 目的
- 忘れた利用者が再導入なしに復旧できるようにする
- 旧パスなしでの維持を不可とし、削除だけを許可する
- 他設定は残し、APIキー再入力だけで復旧できるようにする

## 構成
- dashboardの保護欄に忘れ入口を追加する
- 二重確認の後に削除処理を実行する
- 削除対象は保護の認証記録と無効化で消す鍵群およびAPIキーのみとする。他設定は残す
- SW側の変更はなし。既存の復号不可の扱いは維持する

## 処理順序
1. 保護有効を確認する。旧パスは要求しない
2. 二重確認を通す
3. 保護関連の記録とAPIキーを削除する
4. 鍵保持を消去し、保護無効の状態にする
5. 監査記録を残し、APIキー再入力を案内する

## 文書
- 復旧手順と削除範囲を明示する
- 旧パスなしでの維持は不可と書く
- `public/PRIVACY.md` と `docs/PRIVACY.md` は同一内容にする

## 試験
- 削除範囲の確認に絞る
- 旧パス不要経路の拒否確認を行う
- 実時間待ちは使わない

## 対象外
- SWへの共有による記録継続は行わない
- 設定全体の初期化は行わない
- 輸出形式の変更は含めない

## 受け入れ条件
- 忘れ入口から保護無効化とAPIキー削除が実行できる
- 他設定が残る
- `npm run validate` が通る
