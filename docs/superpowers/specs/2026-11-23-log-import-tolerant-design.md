# 閲覧ログの寛容インポート設計

日付: 2026-11-23
対象: Issue 215。旧版由来の欠損行があっても有効行を取り込む。

## 背景
現行取込は単一形状のみを受け付ける。行検証で全行が落ちると `No valid records found` で全体中断となる。旧版は別名や別構造の可能性があり、行別理由が出ないため利用者は直し方も分からない。

## なぜなぜ分析
1. なぜ中断するか。全行が必須検証で落ちるため
2. なぜ落ちるか。旧形は別名や別構造の可能性があるため
3. なぜ受入れないか。現行は単一形状のみ受入れのため
4. なぜ直せないか。行別理由の報告がないため
5. なぜ救済できないか。0件で全体中断となるため

## 構成
- 受入れ形状は現行rows配列に加え、旧キー形式と単独配列を受け付ける
- 別名は日時と表題と要約と標識を読替える
- 欠損値は空文字や既定に補う。必須のurlと日時は補完しない
- 署名は現行路を維持する。移行路は確認後に素通しする
- 取込は既存の重複無視の性質を使う。同一urlと日時は既存優先で読飛ばす

## 報告
- 不良行は除いて有効行を取り込む
- 修正不能な形式の行は理由と件数で報告する
- 先頭事例を示し、0件時の文言は理由つきに変える
- 再取込は冪等とする。重複は既存を有効として数える

## 処理順序
1. 大きさ確認の後に本体を読む
2. 形状を判定して行一覧に整える
3. 別名を読替えて検証する
4. 有効行をまとめて取込む
5. 件数と理由内訳を返す
6. 失敗行が残る場合のみAI修復ボタンを出す
7. 選択行の修正案を差分で示し確認後に再検証して取込む

## AI修復
- 規則で直せる行は規則で直し残りだけAI対象とする
- 送信は失敗行のみとし事前に汚染除去する
- 件数と文字量に上限を設ける
- 自動送信と自動取込はしない
- 鍵のロック中はAI修復を使えない案内にする
- 利用は明示操作のみとし監査記録を残す

## 試験
- 形状別の受入れに絞る
- 読替えの確認に絞る
- 報告内容の確認に絞る
- 再取込の冪等の確認に絞る
- AI修正案の差分確認と再検証に絞る
- 送信抑止の確認に絞る
- 実時間待ちは使わない

## 対象外
- 署名方式の変更は行わない
- 必須欠損の既定補完は行わない
- 輸出形式の変更は含めない

## 受け入れ条件
- 旧形ファイルの有効行が取り込める
- 修正不能行の理由と件数が分かる
- 同一ファイルの再取込で二重登録が起きない
- `npm run validate` が通る
