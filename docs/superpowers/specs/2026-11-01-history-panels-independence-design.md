# 履歴パネルの独立化設計

- 日付: 2026-11-01
- 状態: 設計承認済み（第1節から第4節まで承認）
- 方式: A案（リージョン移植）
- 目的: 「保存済みコレクション」「履歴に聞く」「調査レポート一発生成」を「履歴」から独立させ、履歴の直後に並ぶ3件のデータパネルにする。

## 決定事項

- 新しいデータパネルを3件作る。履歴の中での分離表示や1パネル集約は採用しない。
- 自動タグ規則は保存済みコレクションと一緒に移す。履歴には残さない。
- 新しい「履歴に聞く」パネルは、保存済みコレクションの一覧を直接読み込む。履歴との共有状態は作らない。
- 新しい「調査レポート」パネルは、保存済みコレクションを選択して対象にする。専用の条件入力欄は新設しない。
- 切り離し後の履歴パネルは、記録一覧と検索操作だけに絞る。新パネルへの導線だけを残す方式や、履歴側への重複残置は採用しない。
- `?tab=history` は履歴パネルのまま維持し、新パネルには新しい deep-link を付ける。
- 新しい3パネルは履歴の直後に置く。

## 第1節 構成・境界

- 履歴（`panel-sqlite-history`）は記録一覧・検索・スター等の記録操作だけに絞る。
- 履歴の直後にデータパネルを3件新設する。
  1. 保存済みコレクション（自動タグ規則を含む）
  2. 履歴に聞く
  3. 調査レポート一発生成
- 新パネルのパネル ID は次のとおり。
  1. `panel-saved-collections`
  2. `panel-ask-history`
  3. `panel-research-report`
- 新パネルは `sidebarSection: 'data'` とし、分類は `analysis` に寄せる。
- 新パネルの `tabParam` は次のとおり。既存の `?tab=history` と衝突しない。
  1. `collections`
  2. `ask-history`
  3. `research-report`
- カタログ順は `panel-sqlite-history` の直後に `panel-saved-collections`、`panel-ask-history`、`panel-research-report` を置き、次を `panel-archive` とする。
- sidebar の文言は既存リージョン見出しと同一文言とし、日英両 locale に追加する。
- 既存リージョン View を新パネルのシェルへ移す。
  - `savedCollectionsPanelView.ts`（保存済みコレクション＋自動タグ規則）
  - `askHistoryPanelView.ts`（履歴に聞く）
  - `researchReportPanelView.ts`（調査レポート一発生成）
- 履歴シェル（`sqliteHistoryPanelView.ts` および `sqliteHistoryPanel.ts`）から3リージョンのプレースホルダ配線を削除する。
- `panelCatalog.ts` を単一の真実の源とし、sidebar 静的 HTML・分類・factory・同期テストの既存規約に従う。

## 第2節 部品とデータフロー

- 保存済みコレクション新パネルは、コレクション CRUD と自動タグ規則を所有する。既存の保存・読込リポジトリを直接使う。
- 履歴に聞く新パネルは、質問文と対象コレクション選択を所有する。一覧は保存済みコレクション取得口から直接読み込む。生成は既存の `askHistoryGateway` 経路のままにする。
- 調査レポート新パネルは、対象コレクション選択と Obsidian 送付オプションと生成ボタンを所有する。生成は既存の `exportResearchReport` 経路のままにする。語・タグ・期間は選択中コレクションから解決する。
- 先頭200件・未読穴・理由表示・再送などの既存制約は変えない。
- 履歴パネルは3リージョンの配線とコレクション読込の責務を持たない。
- 新しい共有状態は作らない。境界は既存のリポジトリとゲートウェイにする。

## 第3節 失敗時・互換性

- 失敗表示は現状維持とする。
  - 質問は拒否理由と再試行を表示する。
  - 報告は対象なし・送信失敗の理由を表示する。
  - コレクション読込失敗は各新パネル内で完結させる。
- 空状態（コレクションなし・規則なし・証拠なし等）の文言と振る舞いは変えない。
- `?tab=history` は履歴パネルのまま壊さない。新パネルには新しい deep-link を付ける。
- sidebar は静的 HTML を維持する。catalog・sidebar・分類・factory の同期テストを更新する。新設 sidebar 文言は日英両 locale に追加する。

## 第4節 テスト・文書・完了条件

- `panelCatalog` 同期テスト、新パネルの存在・順序・分類テスト、既存リージョン描画テストの移設と更新を行う。
- `?tab=history` 維持の回帰確認を行う。
- `docs/SETUP_GUIDE.md` と `README.md` の履歴節を新パネル構成に合わせて更新する。
- 完了条件は次のとおり。
  - 履歴パネルに3リージョンの配線が残っていない。
  - 新パネルが履歴を開かずに単独で使える。
  - 既存の履歴リンクが壊れない。

## 対象外

- 記録パイプライン本体の変更は行わない。
- 要約・モデル・保存条件の仕様変更は行わない。
- E2E の新規追加は実装計画側で必要性を判断する。
