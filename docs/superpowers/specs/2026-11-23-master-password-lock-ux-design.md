# マスターパスワードのロック中案内と操作制限の設計

日付: 2026-11-23
方針: A+C。案内改善とロック中の変更禁止。SW共有は対象外。

## 背景
マスターパスワード有効時は恒常ロックになる。設定直後は `IS_LOCKED=true` で開始する。dashboardで `unlockWithPassword` を呼ぶと `IS_LOCKED=false` になるが、鍵とパスワードの保持場所は文脈別メモリになる。このためdashboard側は復号できても、SW側の `cachedMasterPassword` は空のままで復号できない。保存成功とAIテスト失敗の分離はこの構造による仕様通りの動きになる。記録のAI要約と保存もSW側で不可になる。

## 目的
- 設定順序を分かりやすくする。先にAPIキー登録と疎通確認を行い、最後に保護有効化とする
- ロック中はAPIキーの変更ができないことを明示する
- ロック中の記録追加と設定変更の不可を画面上で止める

## 構成
- dashboard: `authGuard.isLocked` の参照でAPIキー欄と保存操作を無効化し、アンロック導線を表示する。AIテストはSW呼び出し前か失敗時にロック文言で止める
- popupと記録: ロック中は状態表示とdashboard誘導を出し、記録追加操作を無効化する
- SW側: 無改修。fail-closedを維持し、復号不可時は現行のロック文言で返す
- 輸出入: 現行通り認証モーダル経由で許可する。輸出時の一時利用とはしない

## 画面と文言
- 共通文言は3点に統一する。保存不可、AI利用不可、記録停止
- 文言例: ロック中はAPIキーの変更ができません。先にアンロックしてください。AIテストと記録のAI処理はロック中は利用できません
- 設定手順の案内: 1 APIキー登録、2 疎通確認、3 保護有効化、の順序を初期設定画面に書く

## 資料更新
- `public/PRIVACY.md` と `docs/PRIVACY.md` は同一内容で更新する
- `docs/SETUP_GUIDE.md` に設定順序とロック中の制限を追記する
- `docs/FAQ.md` に保存成功とAIテスト失敗の分離理由を追記する

## 試験
- 単体: ロック時の無効化表示、不足時の拒否、文言分岐
- 統合: マニュアル操作の導線確認。実時間待ちは使わない
- E2Eは最小限とし、操作導線の確認に絞る

## 対象外
- SWへのパスワード共有による記録継続は行わない
- 分割バックアップ形式の変更は本件に含めない

## 受け入れ条件
- ロック中にAPIキー変更操作が実行できない
- AIテスト押下時に原因が特定できる案内が出る
- 設定順序が文書だけで理解できる
- `npm run validate` が通る
