# アーカイブ機能 手動テストチェックリスト（優先度別）

> v6.7.114 / PBI 2026-09-06-01〜07 対応。
> E2Eでカバーできていない項目のみを優先度別に整理。
> **準備**: `npm run build` → `chrome://extensions` で Load unpacked（dist/chromium-mv3）→ 閲覧履歴がある状態でテスト開始。

---

## 🔴 必須（リリース前・データ信頼性）

| # | 検証項目 | 手順 | 期待結果 | なぜE2Eで不可 |
|---|---------|------|---------|--------------|
| R1 | 退避 .db の内容照合 | フェーズA実行→ダウンロード→DB Browser for SQLite で開く | `browsing_logs` に退避件数分のレコード、`yasumaro_archive_meta` にメタ（record_count / max_id / format_version=1）。FTS5テーブル・トリガーは**存在しない** | E2Eはファイルサイズのみ検証（内容照合不可） |
| R2 | 境界日のタイムゾーン | OSタイムゾーンを Asia/Tokyo 等に設定→境界日=レコード作成日でプレビュー→件数確認→翌日で再確認 | 境界日当日のレコードが含まれ、翌日は除外される（UTC/local変換ずれの目視担保） | E2Eは実行マシンのTZ固定 |
| R3 | フェーズA後の本体不変 | フェーズA実行→History パネルを開いて件数・内容を確認 | **1件も削除されていない**（削除はフェーズBのみ） | E2Eは件数をAPI照合するが、目視でHistoryパネルを確認するのが最終担保 |
| R4 | single-flight（2タブ競合） | オプションを2タブで開き、両方でアーカイブ作成を実行 | 片方が「already in progress」で拒否され、もう片方が正常完了する | E2Eは1タブのみ |
| R5 | VACUUM による領域解放 | フェーズB実行前後で診断パネルまたは `chrome://settings` のサイトデータ使用量を比較 | 削除＋VACUUM後、OPFS使用量が減少している | E2EはOSレベルの使用量を取得できない |
| R6 | レジストリ消失時のfail-closed | オプションを長時間放置（offscreen再起動）→フェーズB実行 | 「再プレビューが必要です」で拒否され、本体は無傷 | offscreen寿命制御はE2Eで再現困難 |

## 🟡 推奨（ストア公開前・UX品質）

| # | 検証項目 | 手順 | 期待結果 | なぜE2Eで不可 |
|---|---------|------|---------|--------------|
| Y1 | ロケール切替（ja↔en） | ブラウザ言語を切替→Archiveパネル再表示→全文言が切替わることを確認 | 表示中の言語に対応した文言が表示される | E2Eはlocale: en-US固定 |
| Y2 | IDB フォールバック環境での拒否 | OPFS非対応モード（シークレット等）でArchiveパネルを開く | 「Archive requires OPFS storage.」エラーが表示され操作が無効化される | E2EはOPFS対応環境のみ |
| Y3 | 編集→保存→ファイルへの書き戻し内容 | 一時オープン→タイトル編集→保存→ダウンロード→DB Browser で変更後のタイトルを確認 | 編集内容がアーカイブ .db に反映されている | downloadイベントが拡張ページで発火しない |
| Y4 | 復元後のレコード内容の目視照合 | 復元後→History パネルで復元分のタイトル・URL・スター状態を確認 | アーカイブ内の値が正しく本体に反映されている | E2Eは件数のみ検証 |
| Y5 | 再読み込み後のセッション再接続 | アーカイブを開いて編集（dirty）→F5で再読込→STATUS プローブでセッション復元されることを確認 | セッションが復元され、検索・一覧が使える（保存は再DL制限） | E2Eはfile://でJS非実行 |
| Y6 | 削除済みレコードを含めた復元 | 「削除済み行を含める」チェックで作成→復元→内訳表示に削除済み件数が含まれることを確認 | restoredDeleted が正しく集計・表示される | E2Eは未作成（作成フローは自動済みだが復元内訳は目視確認） |

## 🟢 任意（細部の確認）

| # | 検証項目 | 手順 | 期待結果 | なぜE2Eで不可 |
|---|---------|------|---------|--------------|
| G1 | トークン失効（60秒） | フェーズA確認ダイアログで60秒以上待つ→実行 | 拒否される→再発行して成功する | E2Eでは待つとタイムアウトになる |
| G2 | モーダルの実キーボード操作 | Tab循環・Esc・起動要素へのフォーカス復帰を実キーボードで確認 | jsdom の focus/keydown 挙動と実ブラウザで一致する | E2Eはfile://でJS非実行 |
| G3 | 検索語のワイルドカードエスケープ | 検索語に `%` / `_` / `\` を含めて検索 | リテラルとして扱われる（ワイルドカードとして動作しない） | E2Eはfile://でJS非実行 |
| G4 | レガシーストア残存の目視 | フェーズB実行→診断パネルまたはレガシー確認ツールで `savedUrlsWithTimestamps` に対応エントリが残っていることを確認 | 実行前確認の開示どおり残っている | レガシーストアの参照はE2Eから不可 |
| G5 | 録画との並行動作 | アーカイブ作成中に通常の閲覧録画が走る | 録画はブロックされず正常動作する（ワーカーのキュー直列化） | E2Eでは録画を発生させにくい |
| G6 | 孤児ステージング掃除 | オプションを強制終了（プロセスキル）→再起動→Archiveパネルを開く | `archive_incoming_*` / `archive_outgoing_*` が掃除されている | プロセスキルはE2Eで再現困難 |
| G7 | quota 不足の実環境拒否 | ディスク残量を意図的に減らしてフェーズBを実行 | 拒否＋日付分割案内が表示される | ディスク圧迫はE2Eで再現困難 |
| G8 | VACUUM 失敗時の注記表示 | VACUUM が失敗する環境（大容量DB等）でフェーズBを実行 | vacuumOk 注記が表示される | 失敗を人為的に発生させるには実DBが必要 |
