# 閲覧履歴をダッシュボードで分析できるようにした — 8 つの分析パネルを追加した話

Yasumaro のダッシュボードで履歴を眺めていたときのことです。「この記事、先週も読んでいなかったか？」と聞かれて、確信を持って答えられませんでした。履歴は SQLite に何千件も溜まっているのに、問いに即座に答えられない。検索はできる。でも「傾向」を答える画面がありませんでした。

## いそがしい人向けの結論

- v6.9.22 でダッシュボードに **8 つの分析パネル**を追加しました。曜日×時間帯のヒートマップ、滞在時間ランキング、ドメイン/URL の top 20 表、タグの期間推移、タグ共起ペア表、ワードクラスタ、タグクラスタ比較です
- すべての計算は **端末内の SQLite に対して行われ、外部送信はゼロ**です
- 共通の期間フィルタ（今日 / 直近7日 / 30日 / 90日 / 全期間 / カスタム）で 8 パネルを横断できます
- ワードクラスタとタグクラスタの既定期間は「直近7日」。普段は直近の関心を、振り返りたいときは全期間を選ぶ、という使い分けを想定しています

## 追加した 8 つのパネル

サイドバーの「データ」セクションに並びます。UI 名は実装そのままです。

| パネル | 答えてくれる問い |
|------|------|
| 時間帯ヒートマップ | 「自分はいつ記録している習慣がある？」（曜日×時間帯 7×24 マス） |
| 滞在時間分析 | 「今月はどのドメインに何時間？」（ドメイン別・タグ別の合計/平均/件数、上位20） |
| ドメイン分析 | 「#トラベル の記録はどのサイトで見ている？」（ドメイン/URL top 20 表） |
| タグクラスタ | 「どのトピックを組み合わせて読んでいる？」（タグ共起グラフ・既存） |
| タグ推移 | 「このタグの興味、最近減ってない？」（週次/月次の記録数推移） |
| タグ共起ペア | 「グラフが苦手でも共起構造を数字で見たい」（上位20ペアの表） |
| ワードクラスタ | 「タグを付けていなくても俯瞰したい」（要約とタイトルからのキーワード共起） |
| タグクラスタ比較 | 「興味は移り変わった？継続している？」（期間の前半/後半を side-by-side） |

はじめてなら、まず「時間帯ヒートマップ」で自分の記録習慣を確認してから、滞在時間分析に進むのが分かりやすいと思います。タグを付けている人には「タグ推移」と「タグ共起ペア」の組合せが効きます。付けていない人向けには「ワードクラスタ」を用意しました。

## なぜ「パネルを 8 個も」なのか

1 つずつ作ると 8 画面ぶんの重複コードになります。実際、素朴に実装し始めた段階では「履歴の読み込み方」がパネルごとに 5 種類にドリフトしていました（リトライの有無・失敗時の表示・上限超過の扱い）。これは保守を始めた瞬間に破綻する形です。

そこで先に共通部品を 2 つ作りました。

**1 つ目は期間フィルタ（`periodFilter`）**。「今日 / 直近7日 / 30日 / 90日 / 全期間 / カスタム」の UI と期間計算を 1 部品にし、8 パネルで共有します。初期値は `getRange()` が単一の真実の源です。「構築中にイベントを発火させない」という契約も明示したので、パネル側は「apply ボタンで読み取る」か「変更を購読する」かを選べます。

**2 つ目はデータ読み込みの集約（`fetchPeriodRows`）**。リトライ・失敗表示・上限超過の判定（取得件数と total の突合）を 1 箇所に置き、パネル側は「期間内の行を渡す」だけになりました。以前は 5 種類にドリフトしていた失敗ポリシーが、今は 1 通りです。

## ワードクラスタは「既存パイプラインの再利用」で作った

ワードクラスタはタグを付けないユーザー向けの機能です。実装の発想はシンプルで、**ページの要約とタイトルからキーワードを抽出し、それを「#キーワード」という擬似タグに変換して、既存のタグ共起パイプラインに流し込む**だけにしました。

- キーワード抽出は `Intl.Segmenter`（granularity: 'word'）を使います。Chrome には必ず入っているため辞書の同梱は不要で、MV3 のバンドルサイズ制約を守れます
- キーワードは英数字のみに制限しています。共起パイプラインのパース（空白区切り・`|` 連結の edge key）を壊さないためです
- 共起計算・描画はタグクラスタと同じコードを走ります。1 つの強みが 2 つのパネルになる

日本語のキーワード抽出品質は、実データでの手動プローブを前提にストップワードと最小長を調整しています（ 英日混在で最長 30 文字超のトークンはノイズとして落とす保険も入っています）。

## タグクラスタ比較は「同じタグは同じ色」にこだわりました

期間の前半と後半を左右に並べるパネルでは、同じタグが左右で別の色に着色されると比較になりません。タグ→色の対応は FNV-1a ハッシュで決めるため、どの期間を比較しても同じタグは同じ色になります。加えて差分一覧（前半のみ・後半のみで出現したタグ）を添えています。

## プライバシーは変わりません

8 パネルすべての集計は、端末内の SQLite（OPFS + FTS5）に対してブラウザ内で完結します。分析のために履歴・タグ・滞在時間がどこかに送信されることはありません。この点は v6.9.0 のときと同じ立場です。

## 次に何をすべきか

分析候補の台帳には、さらに次の 5 つが RICE 付きで残っています。

- 再訪分析（同じ URL への再訪回数）
- スター分析（★ を付けた記録の傾向）
- 記録量ストリーク（記録が途切れていないか）
- AI 利用統計（provider/model 別の要約回数とトークン消費）
- プライバシー統計（マスキング・プライベート検出の件数推移）

いずれも既存カラムだけで実装可能なため、使ってみて「これが欲しい」というものから着手するつもりです。使ってみて、パネルの見せ方や「こんな切り口が欲しい」という要望があれば、Issue で教えてください。

実装の詳細は [CHANGELOG](../../CHANGELOG.md) の [6.9.22]、使い方は [Data Analytics Guide](../DATA_ANALYTICS_GUIDE.md) にまとめてあります。
