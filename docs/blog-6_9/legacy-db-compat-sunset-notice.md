# 旧データベース互換コードは 2026-12-17 に提供終了します — 更新していない方だけ、一度確認を

Yasumaro は 2026-07-17 の v6.5.34 で、履歴保存の仕組みを旧エンジン（wa-sqlite）から新エンジン（FTS5 対応の SQLite WASM）へ切り替えました。切り替えの際、旧形式のデータベースに保存されていた履歴を新しいデータベースへ自動的に引き継ぐ「移行コード」を同梱しています。

この移行コードには、導入から 6 ヶ月の保持期間を設けています。期日は **2026-12-17** です。期日を過ぎてリリースされるバージョンから、この互換コードを取り除く予定です。それに先立って、利用者のみなさんへ状況と確認方法をお知らせします。

## いそがしい人向けの結論

| あなたの状況 | やること |
|---|---|
| 2026-07-17 以降に一度でも更新して使っている | **何もしなくて大丈夫です**。移行は自動的に完了しています |
| それ以前から使っていて、ここ数ヶ月更新していない | **2026-12-17 までに最新版へ更新し、拡張機能を一度開いてください**。それだけで移行が走ります |
| 最近インストールしたばかり | 何もしなくて大丈夫です（旧データベースが存在しないため、移行は即座に「完了」になります） |

締め切りを過ぎても、データが消えることはありません。旧データベースのファイルはディスクに残ります。ただし拡張機能からは読めなくなり、ダッシュボードには旧分の履歴が表示されなくなります。

## なぜ締め切りが必要なのか

Yasumaro はテレメトリを一切収集しない設計です。すべての閲覧データがローカルに留まる代わりに、「何人のユーザーがまだ移行を終えていないか」を開発側は知る手段がありません。

そこで、移行導入から 6 ヶ月という猶予期間を設けて「この時点なら更新していない人は相当少ないはずだ」という判断を可能にしました。判定材料は次の 2 つです。

1. 日時が 2026-12-17 以降であること
2. 移行ステータスに関する genuine（実際の旧データベースを持つユーザー由来）の「未完了」報告が、support / Issues に届いていないこと

もし報告が集まった場合は、削除を延期して案内を表示した上で、再度猶予期間を設けます。つまりこの予告は「必ず消します」ではなく、「**期日までに更新しておけば間違いなく引き継がれます**という確約と、延期条件の透明化」です。

## 自分の移行状況を確認する方法

ダッシュボードの**診断パネル**に「旧データベース移行」というセクションがあります。

- **完了** … 移行済みです。何もする必要がありません
- **未完了（該当データがない場合を含む）** … 新規インストールの場合はこれで正常です。旧バージョンからの継続利用でこの表示のままの場合は、後述の issue までお知らせください
- **確認中** … 移行処理の実行直後の一時的な表示です。拡張機能の再読み込みで解消することがあります

詳細な仕組みは[移行ガイド](https://github.com/armaniacs/Yasumaro/blob/main/docs/MIGRATION_GUIDE.md)にまとめてあります。

## 締め切り後に何が変わるのか

互換コードを取り除くと、拡張機能は少し小さく、シンプルになります。

| 項目 | 現在 | 締め切り後（見込み） |
|---|---|---|
| Firefox 版 zip | 2.76 MB | 約 2.15 MB |
| Chromium 版に同梱される未使用の旧 WASM | 558 KB | なし |
| 構成 | SQLite バイナリ 3 種 | 1 種 |

移行コードが担っていた「旧 wa-sqlite バイナリの同梱」がなくなることが主な削減源です。機能面の変化は、旧形式データベースの読み替えができなくなることだけです。記録・検索・PII マスキング・同期といった通常の機能には影響ありません。

## Q&A

**Q. バックアップを取っておいたほうがいいですか？**
A. 移行済みの方は不要です。念のため確実にしたい場合は、ダッシュボードのエクスポート機能（SQLite `.db` または JSON）を一度実行しておくと安心です。

**Q. 2026-12-17 を過ぎてから更新したら、旧履歴はどうなりますか？**
A. 旧データベースのファイルはディスクに残りますが、拡張機能はそれを読まなくなります。締め切り前であれば、更新して一度開くだけで自動的に引き継がれるため、期日前の更新をおすすめします。

**Q. しばらく使うのをやめていて、これから戻ってくる予定です。**
A. まさにこの予告の主対象です。2026-12-17 までに最新版へ更新し、拡張機能を一度開いてください。診断パネルの「旧データベース移行」が「完了」になれば引き継ぎ完了です。

**Q. Firefox でも同じですか？**
A. 旧エンジンは Firefox 版には存在しないため、Firefox ユーザーは最初から対象外です。ただし締め切り後のクリーンアップは Firefox 版のダウンロードサイズ削減（約 0.6 MB）にもつながります。

**Q. なぜ「未完了」なのに何も起きないのですか？**
A. 移行は新エンジンの初期化時に一度だけ走ります。「未完了」のまま止まっている場合は、移行処理が完了フラグを書き込めていない可能性があります。保存済みデータには影響しないため情報表示上の扱いですが、**旧データベースをお持ちの方にとっては重要な状態**です。その場合は本予告の issue まで報告いただけると、削除の延期判断に直結します。
