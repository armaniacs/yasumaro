# PBI: PIIスキャナのマルチバイト空白セパレータ対応（全角スペース等）

## ユーザーストーリー
日本語ページを記録するYasumaroユーザーとして、全角スペース（U+3000）等で整形された電話番号・マイナンバー・クレジットカード番号もAI送信前にマスクされることがほしい。なぜなら、整形の書き方次第でPIIが素通しするのは保護の一貫性が壊れているから

## 優先度
- 順位: 2 / 全3候補（台帳: `pbi/2026-09-19-00-backlog-post-v699.md`）
- RICEスコア: 32（Reach=20 / Impact=2 / Confidence=0.8 / Effort=1.0人週）
- 根拠: PII保護（プロダクトの核心価値）の網羅性ギャップだが、発生は「全角空白区切りのPIIを含むページ」に条件付きで、Reachの推定確度が80%止まり。順位1のCI緑化がこの候補の検証（cargo test・パリティ・再ビルドゲート）の土台でもあるためスコア順を維持

## 状況
- JS `\s` の非ASCIIメンバー（U+00A0, U+1680, U+2000〜U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF）は、TS正規表現の `[-\s]` / `[-.\s]` 文字クラスでは区切りとしてマッチするが、WASMスキャナは未対応（素通し）
- 既知の制限として `wasm/pii-sanitizer/src/patterns/common.rs` に文書化済み（ASCII改行 `\n\r` は2026-09-19に対応済み）
- 原因: セパレータ消費がすべて1バイト前提（`is_sep(bytes[p])` → 1バイト進む）。マルチバイト文字は2〜3バイトで、後続の桁消費がずれる
- 対象呼び出し箇所: `is_sep` / `is_sep_dot` の利用22箇所（core5.rs・extended.rs）

## BDD受け入れシナリオ
Scenario: 全角スペース区切りの電話番号がマスクされる
  Given 「TEL 03　1234　5678」を含むページ内容がある
  When  記録パイプラインのPIIサニタイズが実行される
  Then  電話番号が `[MASKED:phoneJp]` に置換され、WASM出力とTS参照出力が一致する

Scenario: 改行なし・半角スペース区切りの従来挙動は不変
  Given 「call 03-1234-5678 now」を含む入力がある
  When  サニタイズが実行される
  Then  既存のマスク結果とbyte-identicalである（既存218件キャプチャ＋52件境界コーパスが全パス）

Scenario: 不完全なマルチバイト列でスキャナが破綻しない
  Given マルチバイト空白の先頭バイトのみが文末に現れる入力がある
  When  サニタイズが実行される
  Then  パニックせず、読み飛ばし（1バイト進行）で安全に終了する
