# PBI: ログのエクスポート・インポートガイドと FAQ を新上限に更新する (docs)

## ユーザーストーリー
閲覧履歴を移行する利用者として、ガイドで現在の上限 (エクスポート 100,000 件、インポート 30 MiB / 100,000 行) を正しく知りたい、なぜなら現行ガイドは 10,000 件 / 10 MiB を記載し、超過時の解決策を一貫して `.db` エクスポート (OPFS のみ) に誘導する。PBI 04/05 の緩和後は数値が乖離し、往復できる範囲の説明も更新が必要だから。

## ビジネス価値
- ユーザーが自分の件数で往復 (エクスポート → インポート) できるかを判断できる
- 上限表を limits.ts の SSOT と突合した値に揃え、誤りを入れない
- 測定方法: ガイドと FAQ の記載数値が src/utils/limits.ts (MAX_EXPORT_ROWS、MAX_IMPORT_TEXT_BYTES、IMPORT_TOTAL_ROW_CAP) と一致すること

```gherkin
  And 上限表が limits.ts の定数と一致する

Scenario: 往復の説明がある
  Given ガイドのインポート節を開く
  Then 「エクスポートしたものはインポートできる」往復の説明がある
  And 100,000 件超の完全スナップショットは .db エクスポート (OPFS のみ) という役割分担が説明されている
```

## 技術的考慮事項
- 依存関係: PBI 04/05 の完了後に実施する (実装確定前の数値を書くと仮数字の文書になる)
- ドキュメント文字規則: AGENTS.md の Documentation Characters (Shift-JIS) に従う。EM DASH (U+2014) 禁止、使用は U+2015。範囲外記号は JIS 相当へ置換
- なぜなぜ分析 30 回: ガイドの停滞は「上限がユーザーに見える挙動」という認識が無く、代替案内 (.db) で穴を塞ぐ運用が続いたため。上限表・往復の説明・役割分担の記載で、実装の進化をユーザー語に翻訳する
- ローカル Markdown 書き出し (MARKDOWN_DOWNLOAD.md 機能、上限 10,000/日付範囲) は本 PBI の範囲外だが、読者が混同しないようガイドの対象パネルを明記する
