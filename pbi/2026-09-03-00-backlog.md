## なぜなぜ分析サマリ

| 疑問 | 原因 → 示唆 → 解 |
|------|------------------|
| なぜ storage が最優先？ | CAS window / post-write verification / canonical equality が4 subsystem に分散し1バグで4 breakage → 1 primitive に統合し fix once に |
| なぜ provider が次点？ | 2つの Map の alias で seam が仮説的、factory switch で新 provider が2箇所に漏れる → catalog が `createStrategy` を own し1行追加で完結 |
| なぜ pipeline が 01 に依存？ | PerUrlMutex スコープと offline heuristic の修正で TOCTOU との切り分けが必要 → 01 で storage 原子性を固めてから mode 分離 |
| なぜ trustDb が shim のまま？ | God Module 分解後も90l shim が全method を再export し境界が enforce されず → Policy/Admin の2 seam で循環を断つ |
| なぜ recordingCache が脆弱？ | 3 TTLs を1つの CacheState と1つの microtask で管理、redact が cache に同居 → 3 typed caches に分割し redact は StoragePort decorator に |
| なぜ domainFilter が重複？ | 4 gates が同じ問いに別staleness で回答、wildcard が3実装 → `DomainFilter` 1 module に統合し cache adapter で2つ目の adapterを用意 |
| なぜ sqlite が speculative？ | Offscreen/Dashboard の2語彙が1クラスに、InMemory が再実装で drift → 分割と共有 builder で fidelity 担保、利用頻度低く優先度は最低 |
