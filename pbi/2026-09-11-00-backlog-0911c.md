## なぜなぜサマリー

- **なぜ previewPresenter がハングするのか** → 4 つの settle path が各自で resolve/reject を管理し、DOM 欠損 path だけが「null 化して return」を選んだため。settle の契約が seam 化されていない。→ 解: settle() 1 箇所に集約（observer 切断・trap release も同時に）。
- **なぜ throttle が trailing を落とすのか** → rAF cancel 方式で「最後の呼び出しを次フレームで再評価」する実装になり、同一フレーム内の同条件再テストが常に false になる。名前は throttle だが挙動は last-call-wins debounce。→ 解: timestamp + timer の素直な leading+trailing に置換。
- **なぜ allowlist が 5 テーブルに分かれたのか** → 機能追加のたびに「その場で必要な表」に足した（manifest 生成・CSP・whitelist gate・fetch origins・provider domains）。→ 解: LIST_SOURCES 単一テーブル + conformance テスト。
- **なぜ limits ガードが半分しか守らないのか** → round 5 PBI 08 のガードを「その時点で問題になった 8 パターン」で止めたため。→ 解: CAPS を吸収済み全値に拡張 + 10MB 同族の吸収。
- **なぜ DeadlineTimer の getter が非対称か** → gate の null 許容は後から追加されたが thresholds は生 `!` のまま残った。→ 解: 対称化。
