## RICE 計算基準

| 要素 | 目安 |
|------|------|
| Reach | 影響ユーザーの推定数（1〜1000） |
| Impact | 0.25=極小、0.5=小、1=中、2=大、3=圧倒的 |
| Confidence | 1.0=100%、0.9=90%、0.8=80%、0.7=70%、0.6=60%、0.5=50% |
| Effort | 日数（0.25=数時間、0.5=半日、1=1日、2=2日、3=3日） |

```
RICE = (Reach × Impact × Confidence) / Effort
```

## 依存関係

- **#03（バリデータ上限）** と **#04（URL スキーム検証）** は同ファイル `validators.ts` への変更。順番通りに実装するか、1つの PR でまとめてもよい。
- **#06（FTS 再構築）** と **#07（マイグレーション文字列マッチ）** は同ファイル `offscreen/migrations.ts` への変更。まとめて実装してもよい。
- **#08（API キー空文字上書き防止）** は High 指摘だが、storage 層の変更が広範囲に及ぶ可能性があるため Effort=1.0（最上位群の中では最大）。前置きなく着手する場合は変更影響範囲の事前調査を推奨。
- **#17（LEGACY_DUAL_WRITE）** と **#18（プロトコルバージョン）** は互換性に関わる設計変更のため、メジャーバージョンアップまたはリリースノートでの明記が必要。
- **#24（SQLite 多重バックエンド）** は工数が大きく（3日見積もり）かつ影響が広範囲なため、「将来対応」または「スパイク調査」として扱うことを推奨。
