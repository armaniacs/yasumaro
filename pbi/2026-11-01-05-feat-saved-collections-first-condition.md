# PBI: 保存済みコレクションの初回条件入力

## ユーザーストーリー

ダッシュボード利用者として、保存済みコレクションの新パネルだけで最初の1件を作りたい。履歴パネルから切り離された後、新パネルに条件入力がないと初期利用者は保存データの用意なしに何も作れず、どこから始めればよいか分からなくなるから。

## 優先度

- 順位: 5 / 6
- RICEスコア: 0.56（Reach=0.2 / Impact=2 / Confidence=70% / Effort=0.5人週）
- 根拠: PBI 01〜04 の完了後に残る初期利用者のつまずき。対象者は新規導入時に限られるため Reach は低いが、空のままでは新パネルの価値が伝わらないため Impact は高い。実装方式（条件入力欄の新設か既存ドラフトからの保存か）は実装時に選べるため Confidence は70%とする。

## BDD受け入れシナリオ

Scenario: 空状態から最初のコレクションを作る
  Given 保存済みコレクションが1件もない
  When 新パネルを開く
  Then 空状態の案内に沿って条件を入力し、最初の1件を保存できる

Scenario: 空のまま保存は失敗扱いで閉じる
  Given 条件が未入力のままである
  When 保存操作を行う
  Then 保存されず、入力が必要な理由がパネル内に表示される

Scenario: 呼び出し後の復元は従来どおり
  Given 保存済みコレクションが存在する
  When 一覧から呼び出す
  Then 条件がパネル内のドラフトに復元される（PBI 01 の契約を維持）

## 受け入れ基準

- [ ] 保存済みコレクションが0件の初期利用者が、新パネル単独で最初の1件を作成できる（条件入力欄の新設または既存ドラフトからの保存のいずれか）
- [ ] 条件未入力の保存は失敗扱いで閉じ、理由をパネル内に表示する（空ドラフトの無言保存をしない）
- [ ] PBI 01 の契約（呼び出しはパネル内のドラフトへの復元まで）を変えない
- [ ] 新設する文言がある場合は日英両 locale に追加し、`npm run check-i18n` が通る
- [ ] 記録パイプライン本体の挙動を変えない
- [ ] 編集した文書が文字種チェックを通る

## テスト戦略

- E2E: 空状態から最初の1件を作成する通し（保存データの用意なしで開始できること）
- E2E: 条件未入力の保存が失敗扱いで閉じること（理由表示の確認）
- 単体: 空状態と入力検証の境界値（未入力・部分入力・正常入力）
