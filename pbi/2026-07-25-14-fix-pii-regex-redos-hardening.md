# PBI: PII検出正規表現のバックトラッキングリスクを軽減する

**作成日**: 2026-07-25
**優先度**: Medium
**見積もり**: 🟡中（2pt目安）
**副作用**: 🟡軽微（検出精度が変化する可能性があるため既存テストでの回帰確認が必要）

---

## 背景

Checking Team レビュー（2026-07-25）の Blue Team Leader（Medium）および Tuning Expert（Low、実行時間不確実性として重複指摘）より。`src/utils/piiSanitizer.ts:24-137` の PII検出パターン（クレジットカード、マイナンバー、IPv4アドレス等）はバックトラッキングを多用する正規表現になっている。

**フェーズ0の事前調査により、以下は既に対策済みであることを確認している**（2026-07-25時点）:
- 入力サイズ制限: `MAX_INPUT_SIZE`（64KB）, `MAX_SKIP_SIZE`（512KB）
- タイムアウト機構: `DEFAULT_TIMEOUT`（5秒）、5マッチごとにチェック
- マッチ件数上限: `MAX_MATCH_COUNT`（1000件）

これらの防御機構により大量CPU消費は一定時間で打ち切られるが、**正規表現パターン自体（`piiSanitizer.ts:245` で複数パターンを `|` 結合した巨大な正規表現）は変更されていない**。パターンの複雑さ自体は残っており、タイムアウトに到達するまでの間にCPUを消費し続ける構造は変わらない。

## 実装者向け注記: 現状の確認

着手前に必ず実行すること:

```bash
grep -n "PII_PATTERNS\|combinedRegex\|MAX_MATCH_COUNT\|DEFAULT_TIMEOUT" src/utils/piiSanitizer.ts
npm test -- piiSanitizer
```

既存のReDoS対策（サイズ制限・タイムアウト・件数上限）が退行しないよう、これらの定数・ロジックは維持したまま、パターン自体の見直しを行うこと。

## 受け入れ基準
- [ ] クレジットカード・IPv4アドレスパターン等、バックトラッキングを多用するパターンを単純化する（例: 固定長の文字クラス `\d{4}` の連続に置き換え、曖昧な量指定子 `+`/`*` のネストを避ける）
- [ ] 異常に長い数字列（閾値は要検討、例: 20桁超）を事前フィルタで除外してからパターンマッチングにかける
- [ ] 既存の `piiSanitizer` テストスイートが全てパスする
- [ ] 悪意のある入力（バックトラッキングを誘発する文字列）でのベンチマークを追加し、処理時間が既存実装より短縮されることを確認する

4. 悪意のある入力でのベンチマークを追加
