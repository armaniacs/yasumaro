# PBI: 暗号化バックアップユーザーガイドの分割形式対応 (docs)

## ユーザーストーリー
暗号化バックアップの利用者として、ガイドで現在の作成と復元の方法 (単一形式と分割形式) と上限を正しく知りたい、なぜなら現行ガイドは単一形式の 50MB 上限だけを記載し、PBI 2026-11-23-01/02 で実装済みの分割形式 (作成時の自動分割、復元時の複数ファイル選択) と PBI 2026-11-26-01/02 による復元上限の改善が説明されていないから。

## ビジネス価値
- 「50MB までしか復元できない」という誤解を解消し、大容量ユーザーが正規の移行手段を利用できる
- 上限の記述を実装の SSOT (limits.ts) と突合した値に揃え、誤りを入れない
- 測定方法: ガイドに記載の上限値と src/utils/limits.ts の定数が一致し、分割形式の操作手順が UI の実際の挙動と一致すること

## 技術的考慮事項
- 依存関係: PBI 2026-11-26-01 (復元ホップ) の完了後に実施する。復元の実効上限の記述が新しい経路 (分割輸送) に変わるため
- ドキュメント文字規則: AGENTS.md の Documentation Characters (Shift-JIS + 列挙済み絵文字) に従う。EM DASH (U+2014) 禁止、使用は U+2015。範囲外記号は JIS 相当へ置換
- PRIVACY.md sync は本 PBI では関係しない (PRIVACY.md を触らない)
- なぜなぜ分析 30 回: ガイドの陳腐化は「ユーザー操作が変わったか」を PBI 作成時に自問するチェックリスト項目が無いこと。本台帳に「docs 更新の要否判定」を DoD に含める運用を記録した

## 実装者向け注記

### 現状コードの確認
(着手前に必ず実行すること)
```bash
grep -n "50" docs/ENCRYPTED_BACKUP_USER_GUIDE.md
grep -n "MAX_BACKUP\|MAX_ENVELOPE\|MAX_RESTORE\|MAX_SPLIT" src/utils/limits.ts
```
確認結果 (2026-11-26):
- ガイドは 15 行 (上限)、65 行 (トラブルシューティング)、79 行、129 行で 50MB に言及
- 分割形式の実装は encryptedBackupPanel.ts (自動分割、複数選択) と encryptedBackupSplitCodec.ts (16 パート、結合後 50MiB)

### 実装手順
1. 現行 UI の実際の挙動 (作成時の自動分割の条件、復元時のファイル選択 UI、不足パートの案内文言) を確認する
2. 上限表を limits.ts の定数と突合して作成する
3. 手順節とトラブルシューティングを更新する
4. `npm run validate` で check-docs-chars を通す

### 落とし穴
- 数値をコードからコピペする際、base64 文字数とバイト数の区別を崩さない (ユーザーに見えるのはファイルサイズ)
- 復元の実効上限は PBI 2026-11-26-01 の実装結果に合わせる (実装前に仮数字を書かない)
