# PBI: マイグレーション失敗判定を文字列マッチから PRAGMA 確認に変更

## ユーザーストーリー
利用者として、起動時のDBマイグレーションがSQLiteの文言変更に左右されず確実に完了してほしい、なぜなら再実行時の冪等判定ミスでDB未初期化のまま動作するとデータ損失・起動不能につながるから

## 優先度
- 順位: 07 / 26
- RICEスコア: 2,800（Reach=1000 / Impact=2 / Confidence=0.7 / Effort=0.5日）
- 根拠: 起動時マイグレーション全体の中断という致命度は高いが、現行文言では正常動作しているため発生確率は将来の依存変更時に限定される。全26候補中で上位の安全性対策として位置づける。

## BDD受け入れシナリオ
```gherkin
Scenario: 再実行時に既存カラム・インデックスがあってもマイグレーションが中断しない
  Given 適用済みのスキーマを持つDBが存在する
  When  起動時にrunMigrationsを再実行する
  Then  既存カラム・インデックスはスキップされ、マイグレーション全体が正常完了する

Scenario: エラーメッセージ文言が変わっても冪等判定が維持される
  Given SQLite WASMのエラーメッセージ文言・ロケール・ラッパーが変更された状態
  When  既存カラムへのALTER TABLEや既存インデックス作成を再実行する
  Then  throwされずスキップ扱いとなり、DBは初期化済みとして動作する
```

## 受け入れ基準
- [ ] 既存カラム・既存インデックスへの再実行が中断なくスキップされること
- [ ] エラーメッセージ文言に依存しない冪等判定になっていること（または許容パターンが定数化されテストで固定されていること）
- [ ] 真の失敗（構文エラー等）は従来通りthrowされること

## テスト戦略
- 単体: 再実行時に既存オブジェクトがスキップされ全体が完了することのテスト、文言違いのエラーでも冪等扱いされることのテスト、真の失敗はthrowされることのテスト

## 実装アプローチ
冪等判定をエラーメッセージの部分一致から、実行前の存在確認（PRAGMA table_info / sqlite_master参照）中心に寄せる方向で見直す。移行過渡期は許容パターンの定数化とテスト固定も選択肢とする。
