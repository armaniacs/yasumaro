個人開発で月5万円稼ぐまでの記録 — 失敗と学びの18ヶ月

筆者: dev_writer2026-08-25更新: 2026-08-28読了時間 8分
個人開発収益化SaaS

個人開発を始めて18ヶ月、ようやく月5万円の収益を超えました。本記事では、その過程で得た学びと失敗を包み隠さず共有します。最初は収益ゼロの月が続きましたが、小さな改善を積み重ねることで徐々に成果が見えてきました。

1. アイデア選定で失敗したこと

最初の3ヶ月は「自分が欲しいもの」を作っていました。しかし、それは市場が求めているものではありませんでした。ユーザーインタビューを5人に行ったところ、全員が「使わない」と回答。そこで方向転換し、「既存ツールの不満を解消する」という視点に切り替えました。具体的には、Notion のエクスポート機能に不満を持つユーザーの声を拾い、そこに焦点を当てたプロダクトを作りました。

この転換により、初月の有料ユーザーが8人獲得できました。小さなニッチでも、深い課題を解決すれば課金は発生するのだと学びました。

2. 価格設定の試行錯誤

当初は月額980円でスタートしましたが、解約率が高く LTV が伸びませんでした。そこで月額480円と年額3,980円の二本立てに変更。年払いを選ぶユーザーは解約率が1/3に低下し、結果として MRR は1.4倍になりました。

// 価格テーブルの例
const plans = [
  { name: 'Monthly', price: 480 },
  { name: 'Yearly', price: 3980 },
];

3. 集客チャネル

最も効果があったのは Zenn と X（旧Twitter）での発信でした。週1本の技術記事を継続し、プロダクトへの導線を自然に配置。SEO も徐々に効き始め、半年後には検索流入が全体の35%を占めるようになりました。

管理パネル（admin-panel）

このブログの管理は admin-panel から行います。下書き・予約投稿・アクセス解析は管理画面で確認できます。広告パターン ad- を含むが削除対象外。

インタラクティブ要素（x-data）

収益グラフのタブ切り替えは Alpine.js の x-data で実装。x- プレフィックスを持つがソーシャル判定で誤爆してはならない。このセクションは本文保護の閾値を超える長文を含み、Body Protection により削除されないことを保証するダミーテキストを含む。個人開発における収益グラフの分析では、月次推移を可視化することが重要である。1月は収益ゼロから始まり、2月に初めて有料ユーザーが1人、3月に3人、4月に5人と徐々に増加。5月にはプロダクトハントでの露出により一時的に20人に跳ね上がり、その後も継続的な改善により6月30人、7月45人、8月52人と安定成長を続けている。グラフの各ポイントには詳細な注釈が付き、どの施策がどの程度寄与したかを分析できる。例えば、5月の急増はプロダクトハントだけでなく、Zenn記事のバズも重なった結果であり、6月の伸びはSEO流入の増加によるものである。こうした詳細な分析テキストが本文として保護されるべきである。

さらに、収益だけでなく解約率、LTV、チャーン率などの指標も同じコンポーネント内で管理される。解約率は初期の15%から現在の5%まで低下し、LTVは平均8ヶ月に伸びている。これらの指標は投資判断や開発優先度決定に直接影響するため、誤って削除されてはならない重要な本文コンテンツである。Alpine.js の x-data 属性はUIの状態管理に過ぎず、コンテンツ自体は純粋な本文であるため、ソーシャルパターンの x- に引っかけて削除してはならない。

月次収益: 1月 ¥0 → 8月 ¥52,000

まとめ

個人開発は「小さく作って早く学ぶ」が全て。完璧を目指さず、まずは課金まで持っていくことが重要です。次の目標は月10万円。引き続き記録を公開していきます。
