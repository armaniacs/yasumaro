## 解釈と次のアクション

- 1000要素で中央値 772.353ms と閾値を超過。1パス集約の検討価値あり。
- 30-05 で `querySelectorAll('*')` 1回 + ルール別 Map分類の PoC を作成し、削除数一致と速度改善を比較すること。
- jsdom 計測は参考値のため、絶対値ではなく比率と閾値判定で判断すること。実ブラウザ計測は `page.evaluate` で同等の `performance.mark` 計測を推奨。

## 再現方法

```bash
node scripts/benchmark-cleansing.mjs
# またはカウント無し:
BENCHMARK_COUNT_QSA=0 node scripts/benchmark-cleansing.mjs
# npm スクリプト経由:
npm run benchmark:cleansing
```

## 計測コードの要点

- `performance.mark(start)` → `cleanseAISummaryContent` → `performance.mark(end)` → `performance.measure` の順で計測。
- 実時間は `performance.now()` 差分を正として採用（`measure` は仕様準拠の記録用に併用）。
- `querySelectorAll` は `Element.prototype` / `Document.prototype` をラップしてカウント（環境変数で ON/OFF）。
