# タグクラスタパネル 目視確認手順（tag-cooccur WASM ハイブリッド）

対象 PBI: `2026-09-20-21`（パネル配線）。`2026-09-20-17`（コア）と `2026-09-20-22`（CI ゲート）の実機確認を兼ねる。

## 判定基準

- WASM 経路で開いたパネルの nodes/edges が、TS 経路で開いたものと同一に見える。
- WASM が使えない状態でも、パネルが空白にならず TS フォールバックで表示される。
- 履歴が 32 件未満のときは TS 経路が使われる（`MIN_WASM_ENTRIES = 32`、`src/dashboard/tagCooccurrenceHybrid.ts`）。

## 準備

1. `npm run build` を実行する。
2. `chrome://extensions` で Developer mode を有効にし、`dist/chromium-mv3` を「パッケージ化されていない拡張機能を読み込む」で読み込む（既に読み込み済みなら再読み込み）。
3. 配布物を確認する: `ls dist/chromium-mv3/wasm/tag_cooccur_bg.wasm` が存在すること。
4. タグ付きの履歴が 32 件以上あるプロファイルを用意する。テスト 3 のために、32 件未満のプロファイルも 1 つ用意するか、履歴を絞り込める状態にしておく。

## テスト1: WASM 経路で表示される（シナリオ 1）

1. ダッシュボード（拡張機能のオプションページ）を開き、サイドバーの「Tag Cluster」（`data-panel="panel-tag-cluster"`）を選ぶ。
2. DevTools の Network タブを開いたまま、パネルを開き直す（別タブへ切り替えてから戻す）。
3. 確認する。
   - [ ] `tag_cooccur_bg.wasm` が読み込まれている（初回のみ。キャッシュされていれば `(memory cache)` 表示でもよい）。
   - [ ] パネルが固まらず、ノードとエッジが表示される。
   - [ ] Console に `fallback` を含む warn が出ていない。
4. 表示内容（ノード数・主要タグ・エッジの太さの傾向）をスクリーンショットで保存する。

## テスト2: WASM が使えない場合のフォールバック（シナリオ 2）

1. `dist/chromium-mv3/wasm/tag_cooccur_bg.wasm` を別の場所へ退避する（削除ではなく移動）。
2. `chrome://extensions` で拡張機能を再読み込みし、ダッシュボードを開き直してパネルを開く。
3. 確認する。
   - [ ] パネルが空白にならず、ノードとエッジが表示される。
   - [ ] テスト 1 のスクリーンショットと、ノード数・主要タグ・エッジの傾向が一致する。
   - [ ] Console に WASM 利用不可の warn が出る（出力は 1 回。プローブ失敗時の warn は連続発生時に間引かれる）。
4. 退避したファイルを元の場所へ戻し、拡張機能を再読み込みする。

## テスト3: 小規模履歴は TS 経路（シナリオ 3）

1. 履歴が 32 件未満の状態でパネルを開く。
2. 確認する。
   - [ ] パネルが正常に表示される。
   - [ ] Network に `tag_cooccur_bg.wasm` の新規リクエストが出ない（他パネルで既にロード済みの場合は判別できないため、拡張機能を再読み込みした直後に確認する）。

## テスト4: 操作性（PBI のビジネス価値の確認）

1. 履歴が最大規模のプロファイルでパネルを開く。
2. 確認する。
   - [ ] 開く際に画面が数百 ms 固まる感じがない（TS 直呼びの実測は約 256ms、WASM は約 46ms。体感の比較で足りる）。
   - [ ] パン・ズームが従来どおり動く。
