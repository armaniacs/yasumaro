## 重要指摘事項（優先度順）

### [High] sqliteClient query/mutate のオーバーロードが QueryOp/MutateOp から乖離
- 指摘者: Legacy Bridge Architect
- 場所: src/background/sqliteClient.ts:92-165
- 影響: QueryOp/MutateOp の SSOT が二重化し、将来 QueryOp にフィールド追加しても sqliteClient 側に反映されずサイレントな不整合になる。sqliteHistoryPanel / tagClusterPanel など呼び出し元が型エラーなく通るため検出が遅れる。
- 対処: オーバーロードの引数型を再び `Extract<QueryOp, {kind:...}>` に戻すか、QueryOp を一元化して sqliteClient は re-export する。移行期間は `satisfies QueryOp` で整合性を静的検証するテストを追加。

### [High] RemoteAIService の ProviderStrategy 型変更が後方互換を壊す
- 指摘者: API & Contract Negotiator
- 場所: src/background/ai/providers/ProviderStrategy.ts:12、src/background/ai/RemoteAIService.ts:30
- 影響: ProviderStrategy のシグネチャ変更が OpenAIProvider に波及し、カスタム Provider 注入が型エラーになる。Dashboard のカスタムプロバイダ設定が壊れる。
- 対処: discriminated union にし旧シグネチャを 1バージョン deprecated として残す。CHANGELOG に breaking change を明記。

### [High] InMemoryStorageAdapter がマイグレーションをスキップしデータ形状が乖離
- 指摘者: Data Integrity Expert
- 場所: src/utils/storage/SettingsRepository.ts:144-150
- 影響: InMemory で `applyMigrationsAndDecrypt(..., false)` にしたことで暗号化 APIキーの復号パスがテストで再現できず、ChromeStorage 側のマイグレーション失敗を検出できない。データ整合性テストの網羅率が低下。
- 対処: InMemory でも `rawEncrypted:true` で復号パスをテストするか、マイグレーション単体テストを分離して両アダプタで共有する。

### [Medium] OpenAI互換プロバイダの baseUrl が検証不足で SSRF 経路になり得る
- 指摘者: Red Team Leader
- 場所: src/background/ai/providerRegistry.ts:1-60、src/background/ai/providers/OpenAIProvider.ts
- 影響: `openai-compatible` / `lm-studio` / `ollama` の baseUrl がユーザ入力で `http://169.254.169.254` 等に差し替えられると内部ネットワークへ到達する。URL allowlist 検証がない。
- 対処: `src/utils/urlUtils.ts` の allowlist で protocol/host を検証し、http の localhost/127.0.0.1 以外を拒否。テストでメタデータサービス URL が拒否されることをアサート。

### [Medium] sqliteClient.callInternal のエラー分類がメッセージ文字列依存
- 指摘者: Blue Team Leader
- 場所: src/background/sqliteClient.ts:58-92
- 影響: catch で `errorMessage(error)` を文字列化してから categorizeError するため、メッセージ文言変更で誤分類する。
- 対処: OffscreenTransport の型付きエラーをそのまま categorizeError に渡し、文字列化はログ出力だけに限定。

### [Medium] perUrlMutex の queue-full 時の握りつぶし
- 指摘者: Blue Team Leader
- 場所: src/background/pipeline/perUrlMutex.ts:58-75
- 影響: maxQueueSize 超過で throw された際、呼び出し元 saveSqliteStep が catch せず Unhandled rejection になる。
- 対処: queue-full 例外を `SqliteRpcResult` の `retryable:true` にマッピングするか、pendingSqliteQueue へ退避。

### [Medium] ServiceContainer が string-key DI で型安全性を失っている
- 指摘者: System Architect
- 場所: src/background/serviceContainer.ts:1-42、src/background/createBackgroundServices.ts:144-218

- 対処: `ServiceTokens` const + `keyof typeof ServiceTokens` で型付けするかブランド型に変更。`_CoreServicesSubsetCheck` を全フィールド比較に拡張。

### [Medium] PerUrlMutexMap の静的共有とテスト隔離のトレードオフ
- 指摘者: System Architect
- 場所: src/background/pipeline/perUrlMutex.ts:14-22

### [Medium] extractor.ts の cleansingConfig 設定で型キャストが残存

### [Medium] テストの大幅削除でリグレッション検出能力が低下
