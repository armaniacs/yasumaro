# PBI: loader.ts の urlSkipper コピーを排除する

## ユーザーストーリー
開発者として、`src/content/loader.ts` にコピーされた `urlSkipper.ts` のロジックを排除したい。なぜなら、70行の重複コードが存在し、コメントで「同期を維持する」と警告されているが、実際には片方の修正がもう片方に反映されないリスクがあるから。

## ビジネス価値
- 重複コードが削減され、保守コストが軽減
- 修正が1箇所で完結し、バグのリスクが軽減
- コードベースの一貫性が向上

## BDD受け入れシナリオ

```gherkin
Scenario: URLスキップロジックの共有
  Given コンテンツスクリプトがページを読み込む
  When URLがスキップ対象である
  Then loader.ts と urlSkipper.ts の両方で同じ結果になる

Scenario: スキップ対象URLの追加
  Given 開発者が新しいスキップ対象URLパターンを追加する
  When 共有モジュールにパターンを追加する
  Then loader.ts と urlSkipper.ts の両方で利用可能になる

Scenario: コンテンツスクリプトの動作
  Given コンテンツスクリプトがページに注入される
  When URLがスキップ対象でない
  Then ページ内容が正しく抽出される
```

## 受け入れ基準
- [ ] 共有URLスキップモジュールが `src/content/urlSkipUtils.ts` に作成される

- [ ] `urlSkipper.ts` が共有モジュールをimportする形に変更される
- [ ] 重複コードが70行削除される
- [ ] 既存のテストがすべてパスする
- [ ] 新しい統合テストが追加される

## 技術的考慮事項
- 依存関係: コンテンツスクリプトの制約（ESM import不可）
- テスタビリティ: 共有モジュールは純粋関数としてテスト可能
- 非機能要件: コンテンツスクリプトのパフォーマンスを維持
