# PBI 記録パイプラインの回復・再試行の正確性

## ユーザーストーリー

記録利用者として、オフラインや競合の発生時も重複実行や回復漏れなく記録されてほしい、なぜなら重複ノートや消失は後始末に手間がかかるから。

## 優先度

順位 07/17。RICE 107 (Reach=200 / Impact=2 / Confidence=80% / Effort=3人日)。根拠は記録の信頼性。PBI 11(Mutex所有権)とは弱い順序関係があり、11を先に着手推奨。

## BDD受け入れシナリオ

### シナリオ1 通常記録が正しく動く ― ハッピーパス

- Given オンラインで同意ありの状態である
- When 記録対象のページ遷移が発生する
- Then 重複なく1件だけ記録される

### シナリオ2 オフライン回復と再試行が正しく動く ― ハッピーパス

- Given 一時的にオフラインになったが同意ありの状態である
- When 回線が復旧し再試行が実行される
- Then 未記録分が重複なく記録され、回復漏れがない

### シナリオ3 同意撤回後の詰まりは新設定で評価される ― エラー/境界

- Given 待機中に同意が撤回された詰まりがある
- When 詰まりの処理が再開される
- Then 撤回前の古い設定ではなく最新の同意状態で評価され、同意なしの記録は行われない

### シナリオ4 ストレージ瞬断で重複実行しない ― エラー/境界

- Given 一時的なストレージ読み取り失敗が発生する
- When 保留中の記録取得が失敗する
- Then 失敗を空扱いにせず、重複実行にならない形で扱われる

### シナリオ5 循環参照を含むデータはキューに入らない ― エラー/境界

- Given 循環参照を含む記録データがある
- When キュー登録時の容量判定が行われる
- Then 0バイト扱いで素通りせず、キューに入らない
