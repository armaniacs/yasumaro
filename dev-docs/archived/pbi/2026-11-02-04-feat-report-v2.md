# PBI: report の V2 対応

## ユーザーストーリー

ダッシュボード利用者として、複数条件や pin 留めのコレクションから調査レポートを作りたい。現行は単一条件のみ読まれ、複数句は黙って縮小・ids は黙って破棄され、全履歴レポートにすり替わるから。

## 優先度

- 順位: 4 / 7
- RICEスコア: 0.56（Reach=0.4 / Impact=2 / Confidence=70% / Effort=0.75人週）
- 根拠: UNION 意味論は本 PBI 内で定義する。records 経路は対応済みのため PBI 01 は不要。

## BDD受け入れシナリオ

Scenario: 複数句のコレクションでレポートを作る
  Given OR の2句コレクションを選んだ
  When レポートを生成する
  Then 両句に合う記録を合わせた Markdown が生成される (先頭句のみへの黙示縮小をしない)

Scenario: pin 留めの ids がレポートに入る
  Given ids 付きコレクションを選んだ
  When レポートを生成する
  Then pin 留め記録が対象に含まれ、欠けた分は除外件数として表示される

Scenario: 合算は200件で頭打ちになる
  Given 合算で200件を超える対象を選んだ
  When レポートを生成する
  Then 先頭200件で生成され、打ち切りの旨が分かる

## 受け入れ基準

- [ ] `ResearchReportScope` に `ids?: number[]` を足し、`normalizeReportScope` と validator の field table を更新する
- [ ] `buildResearchReportScopeFromCollection` を `parseCollectionQueryV2` + `resolveCollectionQueries` ベースに切り替える
- [ ] ids+clauses の結合意味論を UNION (clause 結果の和集合に ids を追加) と定義し、コードとテストに明記する
- [ ] 生成器は fan-out (clause 毎に ids 取得) → UNION → ids 一括 rows (`orderBy created_at ASC` + 先頭200件打ち切り) とする
- [ ] 削除済みで欠けた ids は件数から除外し、除外件数を表示する (欠けをエラーにしない)
- [ ] 200件超の保存時拒否はしない (report 側の打ち切りで吸収する。B とは別扱い)

## テスト戦略

- 単体: scope 正規化の V2 テスト (複数句・ids・合算打ち切り)
- 単体: UNION 意味論のテスト (重複排除・欠け除外)
- 統合: report E2E の既存通し (生成→Markdown→Obsidian 送付の回帰)
- 回帰: `researchReportGenerator.test.ts` 全緑
