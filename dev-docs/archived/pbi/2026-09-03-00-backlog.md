**RICE定義:** `Score = (Reach × Impact × Confidence) / Effort`。Reach は期間あたり影響トランザクション数（1=全呼び出しに影響するが頻度は小さい操作も含む）、Impact は 3=圧倒的 / 2=大きい / 1=中、Confidence は 0.5〜1、Effort は人週。CRITICAL 4件はいずれも Impact 3 で横並び、Effort の小ささで 03 が突出。

**Tie-break:** 01 と 02 は同点 4.8。リスク軽減効果で SSRF（外部攻撃者が provider URL を制御できる）を trust-policy（内部 correctness だが全ページで恒常的に誤判定）より先置き。いずれも独立のため順序入替は許容。

## 推奨着手順

1. **03 confirm-token fail-closed** — 最小 Effort で最大 Impact。破壊的操作の fail-open を即座に塞ぐ。単独 PR で hotfix 可能
2. **04 domain-filter mode inversion** — 毎ページ発現するフィルタ反転を修正。TTL hit の間欠バグのため再現テストが鍵
3. **01 SSRF allowlist bypass** — providerCatalog の pure function を CIDR 範囲で堅牢化。整数/hex/IPv6 の迂回を塞ぐ
4. **02 trust-policy orphan singleton** — fallback 撤廃と stale cache 排除。循環 import に注意し `globalThis.__trustDbKernel` 経由で委譲
5. **05 cleanup** — orphan exports / dead mocks / shim importers を一括除去し `optimisticLock.ts` を物理削除。A/B と C は並行可、C1→C2 は直列

> 01〜04 はいずれも独立のため、レビュアー帯域があれば 03+04、01+02 の2本並行も可能。05 は dev/CI のみでユーザー影響なしのため最後にまとめてもよいが、次の shim 物理削除 iteration を block するため 01〜04 と並行着手可。
