# PBI sessionStoreの耐久性と失敗可視化

## ユーザーストーリー

拡張機能利用者として、セッション状態がSW再起動や容量・quota超過で黙って失われないようにしてほしい、なぜなら状態消失は記録欠落や半端なデータの読み戻しにつながるから。

- RICE: 160 (Reach=300 / Impact=2 / Confidence=80% / Effort=3人日)
- 根拠: データ消失系7件の一括対処

## 背景となる指摘

対象はいずれも src/background/sessionStore.ts の検証済み7件である。

- (1) :238-268 容量超過時は優先サブキーのみ保存し、残りは2回再キュー後にWARN一発で破棄され、半端形状が正規読戻される
- (2) :280-312 quota超過はmemoryに戻すのみで再スケジュールせず、次回set()まで宙ぶらりでSW終了と共に消える
- (3) :100-121 localFallbackCheckedKeysの寿命内メモ化が一過性失敗も確認済みにし、正当な移行を抑止する
- (4) :117-119 get()が全例外を握り潰してnullを返す。missと読取失敗の区別ができない
- (5) :22-26,123-137 set()既定50msデバウンスでflushImmediately指定忘れはSW終了で消失する
- (6) :374-410 onSuspend退避は自認best-effortのfire-and-forgetである
- (7) :305-312,351-364 waitForFlushはflush中追加入りで生まれた新タイマーを待たない

```gherkin
Scenario: 通常のsetとgetとflush後readの順序が保たれる
  Given 空のセッション状態がある

```

```gherkin
Scenario: 容量超過時は黙って半端保存しない
  Given 保存容量の上限に近い状態がある
  When 上限を超える状態をsetしてflushする
  Then 半端形状が正規データとして読み戻されない
  And 失敗または再試行が検出可能な形で残る
```

```gherkin
Scenario: quota超過と再起動でデータが宙ぶらりにならない
  Given quota超過が発生した状態がある
  When 再試行とSW再起動を経て状態を読む
  Then 未確定データが確定済みとして扱われない
  And 利用者が結果を検出できる形で残る
```
