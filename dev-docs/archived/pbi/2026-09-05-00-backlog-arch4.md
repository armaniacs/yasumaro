## 5 Whys サマリー（ラウンド共通の根本原因）

1. なぜ utils が background を参照したのか → 許可チェックの「データ」と「判定」が catalog に同居し、低層に置く場所がなかったから。
2. なぜ merge がロック外なのか → flush 用のロックと enqueue 用の直書きが別々に成長し、結合政策の所有者が決まらなかったから。
3. なぜ popup に薄いラッパーが残ったのか → Round 3 のセッション化で本体は集約したが、wrapper 2 件の削除が見送られたから。
4. なぜ VALID_VISIT が二重構築なのか → 自動記録と手動取得が別々に成長し、共有ビルダーの所有者が決まらなかったから。
5. → 解: データの置き場所・政策の所有者を1モジュールに決める（本ラウンドの7件）。
