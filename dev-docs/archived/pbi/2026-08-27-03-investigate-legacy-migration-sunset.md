# PBI: 旧wa-sqlite移行コードの終息判断【現時点では未着手】

> **この PBI は将来実装するためのものであり、現時点では着手しない。**
> [02: 診断パネルへの旧DB移行状態表示](2026-08-27-02-feat-migration-status-diagnostics.md) の運用実績が
> 一定期間蓄積されるまで、判断を保留する。

## ユーザーストーリー

開発者として、旧wa-sqlite製DBからの移行コード（`opfsMigrationV2Reader.ts` /
`migrationBackup.ts`）をいつ終息（新規ユーザーへの提供打ち切り）してよいかの判断基準を持ちたい、
なぜなら移行未完了ユーザーが残っている状態で移行コードを削除するとデータ喪失につながるが、
外部送信テレメトリなしでは普及率を正確に把握できないから。

## 優先度

- 順位: 03 / 4
- RICEスコア: 6.0（Reach=5 / Impact=2 / Confidence=60% / Effort=1）
- 根拠: 移行導入は v6.5.34（2026-07-17）、現行は v6.7.81（2026-08-26）で約1ヶ月10日経過。
  Chrome拡張の自動更新特性からアクティブユーザーの大半は経由済みと推定できるが、実測値がない
  ため確信度は中程度（60%）にとどめる。**[02](2026-08-27-02-feat-migration-status-diagnostics.md)
  の診断表示が一定期間運用され、サポート問い合わせ等で「未完了」の実例が出ないことを確認して
  から着手すべき依存関係にある。**
- 外部送信テレメトリ（匿名集計によるフラグ普及率の把握）は技術的には可能だが、現在の
  プライバシー方針（全ブラウジングデータをローカル処理、`docs/PRIVACY.md`）との
  正面衝突を伴う大きな決定であり、本PBIのスコープには含めない。必要になった場合は
  別途プライバシーポリシー変更を伴う独立の意思決定として扱う。

## BDDシナリオ

Scenario: 十分な運用期間を経て移行未完了の報告がない
  Given [02]の診断表示が一定期間（目安: 数ヶ月）運用されている
  When  サポート窓口・Issue等に「移行未完了」の報告が一定期間ない
  Then  移行コードの終息（新規リリースからの除去）を判断してよいとみなす

Scenario: 移行未完了ユーザーが一定数存在することが判明した場合
  Given [02]の診断表示や問い合わせから未完了ユーザーの存在が確認される
  When  終息判断のタイミングを迎える
  Then  終息を延期し、猶予期間の告知（アップデート必須の警告表示等）を検討する

## 受け入れ基準

- [x] 終息判断のための具体的な基準（運用期間の長さ、許容する未完了報告件数）を定める
  - **結論: 診断表示（PBI-02）の運用開始 (v6.7.82, 2026-08-27) から 3ヶ月 (2026-11-27) までを観測期間とする。** Chrome拡張の自動更新は通常 2-4週間で 95% 以上の既存ユーザーが新バージョンに到達するが、長期未起動ユーザーを考慮し 3ヶ月とする。期間中に GitHub Issue / サポート窓口 / レビューで「移行未完了（診断で `idb_migration_v2_done: false` かつ `opfsMigrationV2Done: false`）」の報告が **0件** であれば終息可能とみなす。1件でも報告があれば猶予とする。
- [x] 判断基準を満たした場合の対応手順（移行コード削除、[04: WASM統合](2026-08-27-04-refactor-consolidate-wasm-bundles.md) 着手）を明文化する
  - **手順:** 1) `src/offscreen/opfsMigrationV2Reader.ts` / `migrationBackup.ts` / `opfsMigrationV2.ts` と `vendor/wa-sqlite/` の残存 `wa-sqlite-async.mjs` 参照を削除。2) `dev-docs/ADR/2026-08-27-limit-policy.md` の `migrationBackup` 記述を削除。3) PBI-04 の WASM 統合 (2.7MB削減) を直後に着手。
- [x] 判断基準を満たさなかった場合の対応（猶予告知、再判断時期）を明文化する
  - **対応:** 終息を 3ヶ月延期し、次回判断を 2027-02-27 とする。延期期間中は `diagnosticsPanel` に「旧DBが検出されました。v6.5.34 以前の長期未更新の方は一度 v6.7.82 を経由してください」のバナーを表示する運用を検討する。

## テスト戦略
