# PBI: apiKeySource を診断ログに出力する

## ユーザーストーリー
開発者として、APIキーの解決出所をログで確認したい、なぜなら書かれるだけで読まれないフィールドは診断価値がなく、キー取り違え調査の当初目的を果たさないから

## 優先度
- 順位: 04 / 7
- RICEスコア: 16（Reach=10 / Impact=1 / Confidence=80% / Effort=0.5）
- 根拠: PBI 07 の仕上げ。フィールドの存在目的（取り違え切り分け）を実現する最小変更

## ビジネス価値
キー取り違えの切り分けがログで完結する。書きっぱなしフィールドがなくなる

## BDD受け入れシナリオ

```gherkin
Scenario: プロバイダー生成時に出所がログに出る
  Given プロバイダーが構築される
  When 初回の診断ログが出る
  Then apiKeySource の値が含まれる
  And キー本体は含まれない

Scenario: ログにキー断片が出ない
  Given 秘密値を持つキーが設定されている
  When 診断ログを出力する
  Then 秘密値の断片も含まれない
```
