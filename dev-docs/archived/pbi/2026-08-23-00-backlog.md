## フェーズ3: なぜなぜ分析 (疑問の自律解決)

### Q1: CSP connect-src を絞るとローカルAI接続が壊れないか？
なぜ絞りたい？ → SSRF面を最小化したい。なぜSSRFが起きる？ → XSSで任意fetchが可能だから。なぜ任意ポートが危険？ → 悪性サイトが `localhost:<any>` を叩けるから。なぜ今は `:*`？ → 手書き16行とCSPが二重管理で乖離したから。→ **解: host_permissions生成をSSOT化し、CSPはそこから `127.0.0.1/localhost × 27123/27124/11434/1234` の8オリジンのみに限定。AI domainsは buildConnectSrcDomains() からの既存リストを継続。**

### Q2: wasm-unsafe-eval は本当に必要か？
なぜ付与されている？ → sqlite-wasm等で必要だった。なぜ常時？ → 条件分岐が無いから。なぜ条件分岐しない？ → どのページでWASMを使うか未整理だから。→ **解: offscreen/dashboardでWASMを使うなら `extension_pages` のみに限定し、不要なら除去。まず `grep -rn wasm` で使用箇所を特定し、必要ページだけに絞るPBI化。**

### Q3: web_accessible_resources はどこまで絞れるか？
なぜ全サイト公開？ → 初期に `http://*/*` で雑に許可したから。なぜ絞れる？ → 実際にcontent scriptからfetchされるのは `content-extractor.js` のみで、iconsは要否を確認できるから。→ **解: resourcesから不要ならicon除外、matchesは `<all_urls>` 相当を維持しつつも Extension manifestのベストプラクティスに従い、特定オリジン不要なら `http://*/* https://*/*` のまま許容だが、不要resourceの削除で面を削減。**

### Q4: PiiSanitizerの暗黙globalはなぜ起きる？
なぜ暗黙global？ → `docs-src/pii-sandbox.ts` が `src/utils/piiSanitizer.ts` をimportするが、ビルド成果物 `docs/assets/pii-sandbox.js` は IIFE で `PiiSandbox` を生成し、new PiiSanitizer() を直接参照する旧版が残っている疑惑。なぜ気づかない？ → docsは手動ビルドでCI無しだから。→ **解: docs-src を正として esbuild の global-name 出力を確認し、存在チェック `if (typeof PiiSanitizer === 'undefined') throw` を追加。**

### Q5: window.PiiSandbox 公開は本当に脆弱か？
なぜ危険？ → 同一origin iframeなら上書き可能だから。なぜdocsで同一origin？ → GitHub Pagesは同一originでiframeを置ける。なぜ今問題ない？ → docsは静的でiframeを置いていない。→ **解: Object.freeze + getter封じは低コストなので実施、origin validationは docsが外部originからpostMessageしないなら不要。PBIでは freeze を必須、origin checkは将来の拡張点として記録。**

### Q6: SBOMは本当に非準拠か？
なぜ非準拠と指摘された？ → レビュー時点のsbom.jsonが最小版だった可能性。なぜ今は準拠？ → 実ファイルは CycloneDX 1.6 + SHA-512 hash + 1000行超のcomponentsを持ち、@cyclonedx/cyclonedx-npm 6.0.0 で生成されている。→ **解: 誤検出。PBIは「検証結果を残しCIで再生成を担保」するbacklogに格下げ。**

### Q7: バージョン同期はなぜ自動化されていない？
なぜ手動？ → wxt.config.ts が `version: '6.7.64'` を直書き、docs/version.json も同様。なぜ気づかない？ → `scripts/check-version-consistency.js` はあるが `build` 時のみで pre-commit ではない。→ **解: package.json をSSOT化し、wxt.config.ts は `import pkg from './package.json'` で読む、docs/version.json はビルド時生成に切替。**
