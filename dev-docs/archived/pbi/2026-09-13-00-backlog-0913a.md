## RICEスコアリング

```
RICE = (Reach × Impact × Confidence) / Effort
```

Reach は影響ユーザー・利用回数の推定、Impact は 2=大 / 1=中、Confidence は実装確信度、Effort は人日。

## なぜなぜサマリー

- **なぜissueテンプレート(46)を最優先にするのか** → issueReportLink(45)の実装がGitHub issue URLの`template=`パラメータを参照するため、テンプレートファイルとPRIVACY.mdの告知文言が先に存在しないと45の受け入れ基準を検証できない。→ 解: ドキュメントのみでEffortが極小の46を先頭に置く。
- **なぜfriction metrics(52)を最後にするのか** → クリック数・ステップ数の基準値は「実際に存在するE2Eシナリオの実測」からしか得られない。47〜50が未実装の状態でしきい値を決めると恣意的な数値になり、CI回帰防止として機能しない。→ 解: 全ユーザビリティE2Eシナリオ完成後に実測して基準化する。
- **なぜdashboard usability(47)がpopup(49)やa11y(50)より後回しなのか** → 47は5シナリオ（navigation/task-flows/search-results/tag-cluster/markdown-export）を1PBIに束ねており、Effortが2.0人日と独立候補群の中で最大。RICEの分母が大きくなりスコアが下がるため、実行順は独立候補群の中で最後になる。
