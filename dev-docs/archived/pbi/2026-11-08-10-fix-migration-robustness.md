# PBI 起動マイグレーションの再試行と状態検証

## ユーザーストーリー
拡張機能利用者として、起動時の移行が一過性失敗でも再試行され、完了状態が正しく判定されてほしい、なぜなら半移行や全量再移行はデータ破損や起動遅延につながるから。

- (3) src/background/migration/migrationState.ts:42-54 ― getStatus値検証なし・getProgressの||0黙り正規化。キー破損で完了済みが未完了扱いになり全量再移行する。

## BDD受け入れシナリオ
```gherkin
Scenario: 通常の起動移行は成功し完了状態が記録される
  Given 未移行の保存状態で拡張機能が起動した
  When 起動マイグレーションが実行される
  Then 移行が成功し完了状態が記録される
  And 次回起動で再移行されない

Scenario: 一過性失敗後は再試行される
  Given 初回の起動移行が一過性失敗で中断した
  When 同世代内で起動移行が再度要求される
  Then 移行が再試行され半移行が残らない

Scenario: 破損した状態値は検出可能な失敗になる
  Given 移行状態の保存値が破損している
  When 完了状態の判定が行われる
  Then 破損は検出可能な失敗として報告される
  And 完了済みを未完了扱いにして全量再移行しない
```
