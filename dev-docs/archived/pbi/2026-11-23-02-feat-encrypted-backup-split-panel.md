# PBI: 分割バックアップのパネル複数入出力と異常系仕上げ

## ユーザーストーリー
履歴の多い利用者として、分割された暗号化バックアップを画面操作だけで入出力したい、なぜならファイルが複数になっても迷わず移行できる必要があるから。

## ビジネス価値
- 分割形式の利用方法が画面上で完結し、移行の失敗が減る
- 上限超過やパート不足の原因が選ぶ前に分かるようになる
- 測定方法: マニフェストとパート群の選択から復元までの操作が案内通りに完了すること

## BDD受け入れシナリオ

```gherkin
Scenario: 分割バックアップを画面操作で復元する
  Given マニフェストと全パートがそろった分割バックアップがある
  When 利用者がマニフェストを選んで復元する
  Then 不足パートの有無が確認され設定と履歴が復元される

Scenario: 不足パートは復号前に案内される
  Given 1パートが不足した分割バックアップがある
  When 利用者がマニフェストを選ぶ
  Then 復号処理に入る前に不足パート番号が案内される
```

## テスト戦略（t_wadaスタイル）

### E2Eテスト
- 分割エクスポートからマニフェスト選択による復元までの画面操作

### 統合テスト
- マニフェスト選択時の不足検出と上限判定
- 単一形式と分割形式の自動判別
- 改ざんパートの拒否

### 単体テスト
- ファイルサイズ事前判定の境界値
- 不足番号の表示内容
- 原因特定文言の分岐

## 技術的考慮事項
- 依存関係: PBI 2026-11-23-01 の分割コーデックに依存する。本PBI単独では着手しない
- テスタビリティ: 実ファイルの複数選択はモックで再現し、実時間待ちは使わない
- 非機能要件: ファイル読込前のサイズ確認を先に行い、巨大ファイルの全文読込を避ける。VULN-036の順序は維持する
- ロールバック手段: 画面上の分割入口を無効化すれば単一形式運用に戻せる。コーデック自体は残してよい

## 実装者向け注記

### 現状コードの確認
着手前に必ず実行すること。

```bash
grep -rn "encryptedBackupPanel\|MAX_BACKUP_FILE_BYTES" src/dashboard --include="*.ts" | grep -v __tests__
grep -rn "downloadBlob\|importEncryptedBackup" src/dashboard --include="*.ts" | grep -v __tests__
```

確認結果:
- 現行パネルは単一ファイルの選択と復号が前提で、複数選択には未対応
- ファイルサイズ事前判定とenvelope長判定は単一データ前提のため、分割対応では判定単位を見直す

### 実装手順
1. Outside-Inでマニフェスト選択から復元までの失敗試験から書く
2. `encryptedBackupPanel` に分割判定を追加する。単一形式か分割形式かを形状で判別し、分割形式ではマニフェスト先行読みにする
3. エクスポート時は `downloadBlob` を複数回呼び、命名規則をマニフェストとパートで統一する
4. 不足、順序誤り、上限超過の文言は原因特定できる形に分ける

### 落とし穴
- 複数ダウンロードの直列化を崩さないこと。同期revokeに戻すと大容量で保存前に消える
- マニフェストだけ読んで復号に入らないこと。パート不足のままKDFに進むと待ち時間が増える
- 単一形式の判定を壊さないこと。`isEncryptedBackupFile` の条件分岐は試験で固定する
