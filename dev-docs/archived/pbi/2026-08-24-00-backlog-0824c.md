RICE = (Reach × Impact × Confidence) / Effort

- Reach: 影響するコールサイト/トランザクション数（6〜10）
- Impact: 3=圧倒的 / 2=大 / 1=中 / 0.5=小 / 0.25=極小
- Confidence: 100% / 80% / 60% / 50%
- Effort: 人週（0.3〜2.0）

同点は「リスク軽減 → 緊急性」の順で #5（小・低リスク）を #4（中・設計変更）より先に。

## PBI再構成（分離・追加・マージ）

- **マージ（merge）**: #5(Sqlite helper)と#7(maintenance singleton)を1本に統合。同一ファイル`sqliteClient.ts`を触り、分離するとマージコンフリクト確実。Effort 0.4+0.3=0.7w、RICEは再計算で17.0。調整コスト削減。
- **分離（split）**: #1(extractor 593行)をthreshold table(#2)と残りgating分割に分解。threshold tableを先行させることで#1のEffortを1.5w→1.2wに低減（次スプリント）。
- **追加（add）**: なし。共通seamの有効化PBIは不要（各PBIが独立seam）。
- **deferred**: #1(extractor残り)、#4(ServiceContainer)、#6(StorageKeys)はEffort大かつ依存ありで次スプリントへ。今回の3 PBIで基盤を固めてから着手。
