# PBI: ビジットレートリミッタの永続化改善

## 問題説明
`src/background/handlers/recordingHandlers.ts` の `visitRateLimiter` はモジュールスコープの `Map<string, number>` で実装されており、Service Worker 再起動時にリセットされる。これにより、長時間アクティブでなかったタブが再アクセスされた際に、急激な記録が発生する可能性がある。

## 優先度
- 順位: 05 / 05
- RICEスコア: 32（Reach=10 / Impact=1 / Confidence=80% / Effort=0.25）
- 根拠: 影響範囲は限定的（SW再起動後の短時間）。現在の動作は意図的だが、改善の余地がある。

## BDD受け入れシナリオ

Scenario: SW再起動後もレートリミットが維持される
  Given ユーザーがタブを開いたままSWが再起動した
  When そのタブのビジットが記録されようとする
  Then レートリミットが適用され、短期間の重複記録が抑制される

Scenario: 通常のレートリミット動作が維持される
  Given 同じオリジンからの複数のビジットが発生する
  When 5秒以内に2回目のビジットが発生する
  Then 2回目のビジットがレートリミットされる

## 受け入れ基準
- [ ] レートリミット状態がSW再起動後も維持される（または適切にTTLでクリアされる）
- [ ] 通常のレートリミット動作が損なわれない
- [ ] メモリリークが発生しない
- [ ] 既存の単体テストがパスする
