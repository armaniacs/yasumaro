# PBI: encrypt() の Base64 エンコード修正

## 問題説明
`src/utils/crypto/primitives.ts` の `encrypt()` は、暗号文を Base64 エンコードする際に `btoa(String.fromCharCode(...ciphertextArray))` を使用している。これは暗号文サイズが大きい場合（~64KB超）に JavaScript の引数制限（最大65536個）でクラッシュする。同一ファイルの `bytesToBase64()` はループ実装で安全なのに対し、`encrypt()` だけが危険な実装になっている。

## 優先度
- 順位: 04 / 05
- RICEスコア: 32（Reach=5 / Impact=2 / Confidence=80% / Effort=0.25）
- 根拠: 影響を受けるユーザー数は少ない（大型ペイロードを暗号化するケース）が、クラッシュした場合の影響は大きい。修正は容易。

## BDD受け入れシナリオ

Scenario: 大型ペイロードの暗号化が成功する
  Given 64KB を超える平文を暗号化する
  When `encrypt()` を実行する
  Then 暗号化が成功し、Base64エンコードされた結果が返される

Scenario: 既存の小型ペイロード暗号化が引き続き動作する
  Given 小さな平文（1KB）を暗号化する
  When `encrypt()` を実行する
  Then 暗号化が成功し、結果が正しく復号できる

## 受け入れ基準
- [ ] `encrypt()` の Base64 エンコードが `bytesToBase64()` と同じループ実装に置き換えられる
- [ ] 64KB を超えるペイロードの暗号化がクラッシュしない
- [ ] 暗号化結果が復号可能である
- [ ] 既存の単体テストがパスする
