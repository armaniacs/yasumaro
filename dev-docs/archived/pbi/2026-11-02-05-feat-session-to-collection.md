# PBI: session からコレクションへの変換

## ユーザーストーリー

ダッシュボード利用者として、リサーチセッションのひとまとまりをコレクションとして残したい。現行は session パネルと collection パネルの間に橋がなく、写し直ししか手段がないから。

## 優先度

- 順位: 5 / 7
- RICEスコア: 0.42（Reach=0.3 / Impact=2 / Confidence=70% / Effort=0.75人週）
- 根拠: D の ids 消費対応 (PBI 02/04) と同時リリースすること。D なしの変換ボタンは置かない。

## BDD受け入れシナリオ

Scenario: セッションを pin 留めで保存する
  Given 記録のあるセッションを選んだ
  When 「コレクションに保存」を押す
  Then ids ピン留めのコレクションが作られ、件数と期間の確認表示が出る

Scenario: 200件超のセッションは保存が拒否される
  Given 200件を超えるセッションを選んだ
  When 「コレクションに保存」を押す
  Then 保存されず、上限超過の理由が表示される (黙って切らない)

Scenario: 空のセッションはボタンが押せない
  Given 記録0のセッションがある
  When 一覧を見る
  Then 変換ボタンが無効化されている

## 受け入れ基準

- [ ] session パネルに単一セッション単位の「コレクションに保存」ボタンを足す (一括変換は作らない)
- [ ] 写像は ids 優先とし、同日セッションに限り日付 clause を併記できる (跨日は ids のみ)
- [ ] タグは全記録同一のときのみ clause 化し、それ以外は ids のみ + 「タグ混在」の注記を出す
- [ ] 200件超は保存時に拒否し、理由を表示する (`MAX_QUERY_IDS` の黙切りにしない)
- [ ] search_query の取り込みは単一値のときのみ候補提示し、自動確定しない (ユーザー確認必須)
- [ ] quotable 0件の session は警告付きで保存する (ブロックはしない。report は穴表示で役立つため)
- [ ] 保存は editor 草稿への復元か命名付き保存かを選ばせ、無言の直接保存はしない
- [ ] D の ids 消費対応 (PBI 02/04) と同時リリースする

## テスト戦略

- E2E: セッション選択→保存→コレクション一覧の通し
- 単体: 写像の分岐テスト (単日/跨日・単一タグ/混在・200件境界・空)
- 単体: ガードのテスト (拒否・警告・無効化)
- 回帰: session パネル E2E の既存通し
