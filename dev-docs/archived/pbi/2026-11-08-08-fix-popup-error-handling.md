# PBI popupエラーハンドリングの可視化と二重実行防止

## ユーザーストーリー

popup利用者として、操作の失敗が無音で隠されず正しく表示されてほしい。なぜなら無音失敗は原因追跡を不能にし、二重送信は意図しない操作になるから。

## 優先度

順位 08/17。RICE 107点 (Reach=200 / Impact=1 / Confidence=80% / Effort=1.5人日)。根拠は失敗の可視化7件の一括対処である。

## 対象範囲

検証済みの指摘7件を対象とする。いずれも利用者から見た振る舞いの問題として扱い、修正手段は本PBIでは規定しない。

1. タブ生成後にpopupが直ちに閉じる場合、生成失敗が利用者にも記録にも残らない
2. 権限またはストレージの取得失敗が表示も記録もなく無視される
3. 一時停止パネルの再初期化時に操作が多重に送られる可能性がある
4. プライベートページ確認ダイアログの二重表示で例外になる可能性がある
5. 同意モーダルの二重表示で例外になる可能性がある
6. 直前のスキップ理由の取得失敗が記録なく空扱いになる
7. 信頼状態の更新失敗が汎用表示に吸収され障害が正常扱いになる

対象ファイルは次の通り。src/popup/navigation.ts、src/popup/contentFetchGateway.ts、src/popup/pausePanel.ts、src/popup/privatePageDialog.ts、src/popup/privacyConsentController.ts、src/popup/skipReasonPanel.ts、src/popup/trustPanel.ts。

## BDD受け入れシナリオ

### シナリオ1 ハッピーパス 通常操作は従来通り動く

```gherkin
Given popupが正常な状態で開いている
When 利用者が通常の操作を行う
Then 従来通りの結果が表示され余分なエラー表示は出ない
```

### シナリオ2 エラー/境界 タブ生成失敗は閉じる前に検出できる

```gherkin
Given タブ生成が失敗する状態である
When 利用者が外部ページを開く操作を行う
Then popupが閉じる前に失敗が検出可能な状態になる
```

### シナリオ3 エラー/境界 失敗は可視化される

```gherkin
Given 権限またはストレージまたは状態取得が失敗する状態である
When popupが関連する情報を表示しようとする
Then 失敗がログまたは画面表示で確認できる
```

### シナリオ4 エラー/境界 ダイアログ二重表示で例外にならない

```gherkin
Given 確認ダイアログまたは同意モーダルが既に表示されている
When 同じダイアログを再度開く操作が行われる
Then 例外にならず表示状態が保たれる
```

## 受け入れ基準

- [x] タブ生成失敗が未処理のままpopupが閉じることがない
- [x] 権限とストレージと状態取得の失敗がログまたは表示で確認できる
- [x] パネル再初期化で操作が多重送信されない
- [x] 確認ダイアログと同意モーダルの二重表示で例外にならない

- [x] 既存の回帰テストが全て通る
