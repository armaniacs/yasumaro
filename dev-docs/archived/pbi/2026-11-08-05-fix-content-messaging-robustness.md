# PBI content script連携の堅牢性修正

## ユーザーストーリー

記録利用者として、content scriptとpopupとSW間の連携が異常系でもハングや判定不一致を起こさないようにしてほしい。なぜなら無応答や世代ずれは記録停止や誤判定として現れるから。

## 優先度

順位 05/17。RICE 120 (Reach=300 / Impact=1 / Confidence=80% / Effort=2人日)。根拠は無応答とハング系の問題が中心であること。

## 対象の指摘

検証で確認された連携上の弱点は次の通り。

1. src/content/getContentHandler.ts:65 付近。抽出と確定の処理に例外時の送り返しがなく、投げられた場合はpopup側への応答が届かず待ち続ける。
2. src/content/selectionCapture.ts:53 付近。選択読み取りの例外を捕まえずに応答処理へ直結し、分離後のwindow条件で待ち続ける。
3. src/content/loader.ts:49 付近。訪問可否の判定で保存値参照の拒否を捕まえず、未処理の拒否により抽出器が入らず記録が止まり記録も残らない。
4. entrypoints/content-extractor.ts:12 付近。初期化の失敗が見えず、設定読み込み失敗時に音もなく時計も動かず受け口だけ残る。
5. src/content/domainPolicyPort.ts:47,67 付近。保存値の読み取り2回が一体でなく、間に設定が変わると種別と一覧の世代がずれる。
6. src/content/contentKernel.ts:486-491 付近。終了直前の非同期送信が送り切りだけで到達保証がなく、速い遷移で省略理由が欠ける。
7. src/offscreen/cleansingOffscreen.ts:96 付近。上限の名はバイト数だが判定は文字数で、絵文字の多い入力で上限を通り抜けて解析が長く占有する。
