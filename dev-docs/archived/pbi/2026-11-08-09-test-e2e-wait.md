## ユーザーストーリー

保守担当者として、WASM初期化 E2E の固定待ちを肯定条件に反転してほしい。なぜなら 500ms 後の absence は配送遅延と成功の区別がつかず flaky 素地だから。

## 背景 (Read確認済み)

- `testDir/e2e/pii-wasm-initialization.spec.ts:85-86`: `local/no-fixed-wait` 除外+ `await page.waitForTimeout(500)` (成功時は console に出ないため条件が作れない、と理由書き)。
- 規定: AGENTS.md は固定待ち禁止、retry 引上げも同列。例外は計時自体か外部 pacing のみ。
- 対照: `testDir/e2e/overcut-guard-recording.spec.ts:106-107` の 30ms は scroll pacing として分離済み。他 spec は expect.poll/waitPolicy 寄せ徹底。
- 方針: 肯定条件に反転 (WASM 初期化完了・storage 書込・PREVIEW_RECORD 解決を expect.poll/waitForMock で待ってから console 表明)。absence しか観測できないなら AGENTS.md 例外節に bounded settle を明示+500ms 上限根拠を残す。
