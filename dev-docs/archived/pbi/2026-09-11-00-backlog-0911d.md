## なぜなぜサマリー

- **なぜ models-dev-dialog に Esc が 2 系統あるのか** → focusTrap 導入（PBI 25）で closeCallback 経由の Esc が追加されたが、それ以前の document keydown が削除されなかった。attach guard は「重複 attach 防止」だけを目的にし「除去」を想定していなかった。→ 解: trap に一本化 + hide idempotent 化。
- **なぜ HTML twin が 2 件残ったのか** → WXT 移行時に静的 HTML から TS 内蔵 DOM 構築へ移行した際、旧ファイルの削除が漏れた。drift（i18n キー名不一致）が既に起きている。→ 解: stub と静的コピーの削除（TS class が唯一の真実）。
- **なぜ i18n 削除が 3 段階になったのか** → round 6 のリテラルスキャンは「第一引数リテラル」しか見ないため、変数経由（union 型リスト・ternary）と動的構築（ruleLabels の template literal）を拾えない。→ 解: substring（tests 込み）→ 動的 prefix 検査の 3 段階。103 件まで縮小して初めて自律削除が安全になる。
- **なぜ privacy の fetch 主張が誤っていたのか** → サブエージェントが dist/chromium-mv3/ の配置を考慮せず「../ がルートを抜ける」と判断した。実検証では ../ は permissions/ からルートへ解決し PRIVACY.md に到達する。→ 解: PBI スコープを hardening に格下げ（getURL 移行）。
- **なぜ release-checks が沈黙するのか** → 各 check が「検査対象の存在を前提」に書かれ、前提が崩れた場合（coverage 欠落・xvfb 無し・権限追加）の失敗経路が無い。→ 解: 前提崩壊を fail にする。
