# PBI: プロファイル間移行の公式モードを用意する

## ユーザーストーリー
Edge・Chrome・Firefoxの間で乗り換えるユーザとして、署名付きのまま設定と履歴を移行したい、なぜなら現状の署名はプロファイル固有鍵 (HMAC secret) に束縛されており、ブラウザを跨ぐ正規の移行手段が存在せず、ソースコードに一時パッチを当てて検証を無効化するしかなかったから

## ビジネス価値
- ブラウザ乗り換え時のデータ移行が公式手順で完結する (サポート負荷の削減)
- 一時パッチのような危険な回避策を使わずに済む
- 測定方法: Edge・Chrome・Firefoxの任意の組み合わせで設定+履歴の移行が成功すること

## BDD受け入れシナリオ

```gherkin
Scenario: 移行モードで別プロファイルへ移行する
  Given 移行元プロファイルのエクスポートファイルがある
  When 移行先で移行モードを明示的に選びファイルをインポートする
  Then 設定と履歴が適用される

Scenario: 通常インポートは従来通り拒否する
  Given 他プロファイルの署名付きファイルがある
  When 移行モードを選ばずにインポートする
  Then 従来通り署名検証失敗として拒否される

Scenario: 移行確認なしでは適用されない
  Given 移行対象ファイルがある
  When 移行確認ダイアログをキャンセルする
  Then 何も変更されない

Scenario: 対応3ブラウザの全組み合わせで移行できる
  Given Edge・Chrome・Firefoxのいずれかのエクスポートファイルがある
  When 同一ブラウザの別プロファイルまたは残り2ブラウザのいずれかで移行モードを選びインポートする
  Then 同一ブラウザ3通りと異ブラウザ6通りの全9通りで設定と履歴が適用される
```

## テスト戦略（t_wadaスタイル）

### E2Eテスト
- 鍵の異なる2プロファイルを模した環境での移行シナリオテスト (Edge・Chrome・Firefoxのビルド差異を吸収できること)
- 通常インポート拒否の回帰シナリオテスト

### 統合テスト
- 移行確認ゲート (確認なしでは適用されないこと)
- 移行適用後の設定・履歴の一致

### 単体テスト
- 移行判定ロジックの分岐 (署名あり他鍵/署名なし/自鍵)
- 確認ダイアログの分岐

## 技術的考慮事項
- 依存関係: PBI 2026-11-06-01/02 とは独立 (単独で着手・完了可能)
- テスタビリティ: HMAC secret を差し替え可能なテスト用 signer で異鍵環境を再現する

## 実装者向け注記

### 現状コードの確認
(着手前に必ず実行すること)
```bash
# 機能に関連するキーワードでコードを探す
grep -rn "verifyExportSignature\|exportHmacSigner" src/ --include="*.ts" | grep -v __tests__
grep -rn "importNoSignature\|different browser profile" src/ _locales/ 2>/dev/null | head -20
```

### 実装手順
1. Outside-In: まず異鍵プロファイル間の移行E2Eテスト (失敗を確認) から書く
2. 移行方式を決める (移行用エクスポート形式 / パスワード認証付き移行 / 明示確認での検証緩和など)
3. 通常経路 (`importSettings` / `verifyExportSignature` / `handleFileImport`) に影響が出ない形で移行経路を追加する
4. Red-Green-Refactor で各レイヤーを実装する

### 落とし穴
- 2026-11-06 の移行作業で使った一時パッチ (`tmp/migrate-edge-to-chrome/allow-unsigned-migration.patch`) のような無条件緩和を製品に残さないこと。必ず明示確認とセットにする
- Firefoxは拡張機能ID・審査 (AMO)・ストレージ backend (IDB fallback) の扱いがChromium系と異なる。ファイル形式はbackend差異を吸収できること (DBバイナリ直結ではなくJSON/envelope経由にすること)
- `setAll` は差分マージなので、移行適用前後の設定差分が分かる表示があると親切
- APIキー除外方針とデバイス固有状態の除去 (`stripDeviceLocalSecurityState` 等) は移行経路でも維持すること
