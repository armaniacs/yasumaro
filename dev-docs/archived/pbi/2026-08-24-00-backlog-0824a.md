## なぜなぜ分析

### PBI-01 SettingsRepository shim の廃止

**現象**: `tryLegacyGetAll`/`tryLegacySave` が本番コードに存在し、テスト seam が漏洩している。

1. なぜ test seam が本番に漏洩しているのか → `settingsStore.legacy.ts` が廃止されていない
2. なぜ `settingsStore.legacy.ts` が残っているのか → テストが `settingsStore.legacy` の `getSettings`/`saveSettings` に依存している
3. なぜテストが legacy に依存しているのか → `InMemoryStorageAdapter` が `DEFAULT_SETTINGS` のみを返し、マイグレーション・暗号化をスキップする
4. なぜ `InMemoryStorageAdapter` がマイグレーションをスキップするのか → テスト用に簡易化されたため
5. なぜ簡易化が必要だったのか → 本番 adapter をテストで再利用する仕組みがなかった
→ **解**: `InMemoryStorageAdapter` に `applyMigrationsAndDecrypt` + `DEFAULT_SETTINGS` fill を追加し、adapter 注入で本番・テストを同一 seam に統一する。shim を削除する。

### PBI-07 Offscreen dispatch guard の集中化

**現象**: 24 ケースの switch が個別に payload size guard を再実装している。

1. なぜ guard が個別に再実装されているのか → dispatch が switch 文で実装されているため
2. なぜ switch 文で実装されているのか → 各ケースの処理が異なるため
3. なぜ処理の共通部分（guard）を抽出しないのか → 設計時に guard が cross-cutting であることが認識されなかった
4. なぜ guard が cross-cutting と認識されなかったのか → 各ケースが独立した handler として見えていなかった
5. なぜ handler として見えていなかったのか → `dispatchSqliteMessage` が monolith だったため
→ **解**: `sqliteMessageHandlers: Map<type, Handler>` に抽出し、共通 `assertPayloadSize` を各 handler の先頭で呼び出す。

### PBI-03 AI Provider typed dispatch

**現象**: `ProviderSlot.provider: string` でプロバイダが識別されている。

1. なぜ string で識別されているのか → プロバイダ追加時に 4 箇所を手動同期する必要があったため
2. なぜ 4 箇所を手動同期する必要があるのか → 文字列リテラルが分散しているため
3. なぜ分散しているのか → `ProviderId` が型として定義されていないため
4. なぜ型が定義されていないのか → 初期実装時に type safety が優先されなかった
5. なぜ優先されなかったのか → プロバイダ数が少なかったため
→ **解**: `ProviderId` union + `ProviderRegistry` を導入し、型レベルでプロバイダを検証する。

### PBI-05 Layer inversion の修正

**現象**: `storageMaintenance.ts` が `background/sqliteClient` に依存している。

1. なぜ utils が background に依存しているのか → `SqliteClient.healthCheck` が必要なため
2. なぜ `SqliteClient` に依存するのか → `ensureStorageQuota` が SQLite の健全性を確認するため
3. なぜ確認が必要なのか → SQLite が異常な場合、古いファイルを削除する必要があるため
4. なぜ storageMaintenance で削除するのか → ストレージ quota 管理の一部として実装されたため
5. なぜ storageMaintenance が quota 管理をするのか → 元の設計で storage レイヤーが quota を担当していたため
→ **解**: `SqliteHealthCheck` interface を Layer 0 に定義し、`createBackgroundServices` から注入する。`storageMaintenance.ts` は background を import しない。
