# PBI: Markdown サニタイズ＋エクスポート集計を Rust/WASM に移植する

## ユーザーストーリー

履歴エクスポート利用者として、数千件の Markdown エクスポートを待ち時間なく完了したい、なぜなら現状はエントリ毎の正規表現4連鎖が 2000エントリで約11ms、1万行規模では数十ms のメインスレッド処理になるから

## 優先度

- 順位: 2 / 4（本計画の P2）
- RICEスコア: 5.6（Reach=4 / Impact=2 / Confidence=70% / Effort=1週）
- 根拠: 実測（初回発見時の実測プローブ。着手時に bench/probe で再計測）で単発 128KB ≈ 1.2ms、2000エントリ集計 ≈ 11ms。正規表現セマンティクスが単純でパリティ容易＝確実に取りに行ける分、Confidence を高めに置いた。速度効果自体は P1 より小さい

## ビジネス価値

エクスポート操作の体感待ち時間の削減と、エクスポート経路の GC 負荷低減。正規表現置換の中間文字列生成を WASM 線形メモリ内に閉じ込める

## BDD受け入れシナリオ

```gherkin
Scenario: エクスポート集計が高速化する
  Given 2000 件のエントリ（各 0.5KB 要約）
  When Markdown エクスポートを実行する
  Then 出力テキストが TS 実装と完全一致し、集計時間が短縮する

Scenario: 悪意ある Markdown が無害化される
  Given `[text](javascript:...)`・`![alt](...)`・`[[wikilink]]`・生 HTML を含む本文
  When WASM パスでサニタイズする
  Then エスケープ結果が TS 実装と bit 等価である

Scenario: エンティティ化の順序が保存される
  Given `&`・`<`・`>` を含む本文
  When サニタイズする
  Then `&` 先行エンコードの順序が再現され二重エンコードにならない
```

## 受け入れ基準

- [x] TS プローブで `g`/`i` フラグ正規表現の `lastIndex` 系挙動と適用順を先に固定する（予測で書かない）
- [x] 新クレート（仮称 `md-sanitize`）。エントリ配列の一括投入→WASM 内で全件変換→`---` 結合まで行う集計エントリポイントと、単発変換エントリポイントの2口設計
- [x] ハイブリッドラッパー: 例外時 TS フォールバック＋サイズ閾値ルーティング（閾値はベンチ実測）
- [x] パリティテスト（Vitest）: TS vs WASM 等価性を攻撃パターン込みで検証
- [x] ベンチで TS vs WASM を実測し正直に報告する
- [x] ビルド配線3箇所と CI 同等性ゲートへの追加、`npm run validate` green

## テスト戦略（t_wadaスタイル・Outside-In）

### E2Eテスト

- 対象外（既存 Markdown エクスポートテストが表示回帰をカバー）

### 統合テスト

- ハイブリッド経由の大入力ケース（サイズルーティング無意味化の罠に注意）
- WASM 失敗時の TS フォールバック

### 単体テスト

- `cargo test`: 各置換段階の単体検証、エンティティ順序、空入力・非文字列ガード
- TS パリティスイート（gate）

## 実装アプローチ

- **Outside-In TDD**: エクスポート結果の一致 → ハイブリッド → Rust コア
- Rust `regex` クレートと JS 正規表現の方言差（先読み等は未使用見込み）を実装前のプローブで洗い出す

## 技術的考慮事項

- 依存関係: なし。実行場所はダッシュボード拡張ページ（CSP 済み）
- 遵守すべき事項: `sanitizeForObsidian` の適用順（Markdown リンク→wikilink→HTML エンティティ）は意味論であり変更不可

> DoD 補足（2026-09-20）: 受け入れ基準 6/6 チェック（プローブ→クレート2口→ハイブリッド→パリティ→ベンチ→配線+CI+validate 12,761 green）。ただし BDD の「集計時間が短縮する」シナリオは**未達**: 実測で WASM が全サイズ TS 負け（single 0.31x〜0.77x、batch 0.57x〜0.64x — メモリ帯域律速、wasm-bindgen の UTF-8 コピーが支配的）のため、**dark-launch**（MIN_WASM_CHARS=1MB / MIN_WASM_TOTAL_CHARS=2MB で全本入力を TS 経路にルーティング、WASM は CI 同等性ゲートで保守）とした。高速化の再挑戦（PBI-23）も非反転で終了したため、**2026-09-21 に dark-launch 配線ごと撤去**（exportLogsService は TS 直呼びに復帰。クレート・ラッパー・バイナリ・CI ゲート一式は git 履歴参照）。同期呼び出し元は元の直参照のまま。
