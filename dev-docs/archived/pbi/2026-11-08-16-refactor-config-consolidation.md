# PBI 定数・上限値の集約と二重管理の解消

## ユーザーストーリー
開発者として、上限値やタイムアウトの定義が一箇所に集約されてほしい、なぜなら二重管理は変更時の直し漏れで層ごとに判定が割れる原因になるから。

## 優先度
- 順位: 16/17
- RICE: 16 (Reach=40 / Impact=0.5 / Confidence=80% / Effort=1人日)
- 根拠: 保守性のみ。新規価値や不具合修正ではなく、将来の変更漏れを防ぐための整理である。

## BDD受け入れシナリオ

```gherkin
Scenario: 通常の上限・タイムアウト挙動は変わらない
  Given 集約前と同じ上限値とタイムアウト値が設定されている
  When 通常の入力と通常の待ち時間で処理を実行する
  Then 処理結果と成功可否は集約前と一致する
  And 層ごとに異なる判定は発生しない

Scenario: 上限変更が一箇所で全層に反映される
  Given 上限値の正規の定義箇所を一つだけ変更した
  When その上限に関わる複数の層で処理を実行する
  Then すべての層で変更後の同じ上限が適用される
  And 旧値が残る層は一つもない

Scenario: 不正設定値は拒否または正規化される
  Given 負数やNaNやInfinityなどの不正な設定値を与えた
  When 設定の読み込みと検証を実行する
  Then 処理は不正値を拒否するか安全な値に正規化する
  And 異常な待ち時間や異常な上限で処理が継続しない
```

## テスト戦略
- 単体テスト中心とする。E2Eは追加しない。

- 回帰テスト: 集約前後で通常の上限判定とタイムアウト判定が変わらないことを検証する。
