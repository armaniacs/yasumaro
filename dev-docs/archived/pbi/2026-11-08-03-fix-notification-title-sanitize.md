# PBI プライバシー確認通知のタイトル無害化

## ユーザーストーリー

拡張機能利用者として、確認通知に表示されるページタイトルが攻撃者に操作されない形で表示されてほしい。なぜなら拡張機能名義の通知文は信頼されやすく、保存の誘導に悪用されるから。

背景(検証済みの指摘):
src/background/notificationPolicy.ts:82-86 と recordingHandlers.ts:164-165 で sender.tab.title (攻撃者が変更できる値) を無加工で補間し、notificationHelper.ts:46-55 が素通しで chrome.notifications.create へ渡している。切詰め、制御文字除去、出所標示がない。

## 優先度

順位 03/17。RICE 240 (Reach=150 / Impact=1 / Confidence=80% / Effort=0.5人日)。根拠: script実行はないが信頼UIへの文言注入になる。工数は極小。

## BDD受け入れシナリオ

### シナリオ1 ハッピーパス: 通常タイトルは従来通り表示される

- Given 通常の長さで制御文字を含まないページタイトルがある
- When プライバシー確認通知が表示される
- Then タイトル内容が従来通り通知文に含まれて表示される

### シナリオ2 境界値: 異常に長いタイトルは切り詰められる

- Given 非常に長いページタイトルがある
- When プライバシー確認通知が表示される
- Then タイトルは定めた長さ上限で切り詰められて表示される

### シナリオ3 エラー系: 制御文字や誘導文言は無害化または出所明示される

- Given 制御文字や保存を誘導する文言を含むページタイトルがある
- When プライバシー確認通知が表示される
- Then 制御文字は除去され、誘導文言は無害化されるか、ページ由来であることが分かる形で表示される

## 受け入れ基準

- 長さ上限、制御文字除去、出所標示のいずれか一つ以上が通知表示前に適用されること
- 上記BDDシナリオに対応する自動テストが存在し、成功すること
- 通常タイトルの通知表示が変わらないこと

## テスト戦略

- 単体テスト: 異常タイトル表(通常、長い、制御文字混じり、誘導文言混じり、空文字)を用意し、表示結果の長さと無害化と出所標示を確認する
