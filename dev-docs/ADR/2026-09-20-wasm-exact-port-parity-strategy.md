# ADR-017: WASM コアの「完全移植 + TS パリティ参照 + ハイブリッドフォールバック」戦略

## Status

**Accepted** (2026-09-20)

## Context

録画パイプラインの計算重い純文字列処理(PII マスキング・TextRank・文冗長除去)を Rust/WebAssembly へ移行してきた。この方針は 3 クレートで事実上適用済みだが、決定記録が存在せず、4 つ目以降のコアや共有化の議論が毎回ゼロからになる。

制約は次の通り。

- **実行環境で WASM 起動可能性が異なる。** Service Worker とオフスクリーン文書は拡張機能 CSP(`wasm-unsafe-eval`)で動くが、コンテンツスクリプトはページ CSP に従うため WASM 起動を保証できない。録画フローはコンテンツスクリプト抽出を含む。
- **正しさの基準が JS 実装にある。** 既存 TS 実装はテストとユーザー観測で挙動が固まっている。Rust 側を「賢く再設計」すると、しきい値境界・Unicode ケースマッピング・split の空隙扱いなどで出力がずれ、テストと実データの双方で乖離コストが跳ねる。
- **再現ビルドゲートがある。** `rust-toolchain.toml` 固定 + `build:wasm` + ci.yml の wasm-test ジョブが、コミット済みバイナリと新規ビルドの振る舞い同等・glue 陈腐化・src/public 一致(出荷時)を検証する。クレートはスタンドアロンで Cargo.lock を持つ。
- **JS 文字列セマンティクスが特殊。** TS 実装は UTF-16 コードユニット基準(`.length`、`charAt` バイグラム、JS `\s`)であり、Rust の `char`/`&str` 直接移植では非 BMP 文字で逸脱する。

## Decision

1. **各 WASM コアは TS リファレンスの完全移植(exact port)とする。** セマンティクスの改善・統合は WASM 側で行わない。挙動差は TS リファレンス側を先に変え、パリティテストで確認してから移植する。
2. **TS リファレンスはツリーに残す。** 役割は (a) フォールバック実装、(b) パリティテストの基準、(c) 挙動の一次仕様。削除しない。
3. **呼び出しはハイブリッドラッパーに統一する。** `initExtensionWasm` による単一初期化、module 単位の可用性プローブ、JS→WASM 数値境界の option ドメインガード(u32 整数域外・非有限値は TS 経路へ)、実行時例外は TS フォールバックへ、を各ハイブリッドが行う。フォールバックは静かに失敗せず warn ログを残す。
4. **Rust 側は UTF-16 コードユニットで動作する。** 各クレートの jsstring 層が JS セマンティクス(空白表・lowercase・バイグラム)を再現する。lone surrogate は U+FFFD になることを許容し、ハイブリッドのフォールバックで吸収する。
5. **コアは選択インデックス + split 総数を返し、JS 側で再構築する。** 文字列の往復コピーを避ける代わりに、呼び出し側が同一 split で再 split し、総数一致とインデックス範囲を検証してから mapping する。
6. **安全上限は fail-open で設計する。** 計算量上限(例: 1000 文上限のペア走査)を超えた入力は内容を落とさず、冗長削減のみ停止する。上限の存在はハイブリッドのドキュメントに明記する。
7. **バイナリはコミットし、CI ゲートで守る。** `wasm-pack build` 産物をコミットし、振る舞い同等(新規ビルドとコミット済みの双方でパリティスイート)+ glue 陈腐化検出 + src/public 一致(出荷時)を ci.yml の wasm-test で検証する。
8. **クレートはスタンドアロンを維持する。** 再現ビルドゲートの単位を崩さない。共有基盤(UTF-16 ヘルパ・トークナイザ)の抽出は、パリティスイートを gate に保持したまま別途行う。

## Consequences

- **利点**: 環境要因(CSP・初期化失敗・将来の Chrome 仕様変更)で WASM が使えない環境でも録画品質が落ちない。移植ミスはパリティスイートで機械的に検出できる。4 つ目以降のコアは「TS 実装 → 完全移植 → ハイブリッド → ゲート追加」の定型的な手順で追加できる。
- **コスト**: TS と Rust の二重実装を保持する。Rust 側の改善は TS リファレンスへの反映を含めて両側で行う必要がある。glue の後処理(postprocess-wasm-glue.mjs)と CI ゲートの保守が残る。
- **共有化の指針**: jsstring/トークナイザのクローンは drift リスク(ハッシャ差分がすでに発生)があるため、共有 Rust crate への抽出を許す。その際も本 ADR の 1〜7 は変わらない。抽出の実行判断はバックログ(PBI)で管理する。
- **违反の扱い**: 「賢い再設計」で TS と挙動が違う WASM コアは、パリティゲートを故意に弱めない限りレビューで受理しない。意図的に差分を入れたい場合は、まず TS リファレンスとパリティスイートの期待値を更新する。
