Yasumaro（旧 Obsidian Weave）は、ブラウザで読んだページを AI 要約付きで記録し、ローカルの SQLite と Obsidian に残す Chrome 拡張機能です。

v6.6.0 から v6.7.116 までのあいだ、リリースの大半はバグ修正と内部リファクタでした。ただ、そのなかにユーザー体験を確実に変える前進が4つあります。この記事はその概観で、詳細は各ディープダイブ記事に譲ります。

## いそがしい人向けのまとめ

| 前進 | 何が変わったか |
|---|---|
| ブラウザ内蔵 AI 対応 | Chrome / Edge のオンデバイス AI で要約できる。API キー不要、オフライン可 |
| コンテンツクレンジングの強化 | 4つのプリセット、サイト別の上書き、Cookie バナー除去、SPA 対応 |
| 閲覧履歴アーカイブ | 古い履歴を標準 SQLite ファイルに退避し、あとで戻せる |
| AI 接続テストの実質化 | 疎通確認ではなく実際に推論を1往復。送受信の中身を画面表示 |

## 1. ブラウザ内蔵 AI に対応した

Chrome の Gemini Nano、Microsoft Edge の Phi-mini を、要約プロバイダーとして選べるようになりました。プロバイダー ID は `built-in-ai` です。

API キーの登録が要りません。モデルはブラウザがデバイス内に持つため、要約時にページ内容が外部へ出ません。初回だけモデルのダウンロード（数 GB）が走り、以降はオフラインでも動きます。

サービスワーカーから直接 `LanguageModel` API を呼ぶ設計で、DOM を必要としないのでオフスクリーンドキュメントを経由しません。ダッシュボードの診断パネルに内蔵 AI 専用のセクションがあり、`LanguageModel.availability()` の状態（`available` / `downloadable` / `downloading` / `unavailable`）とダウンロード進捗をそこで確認できます。

設計の狙いは「キーもネットワークも用意できない人に要約の入口を1つ増やす」ことです。速度はクラウド API に劣りますが、記録はバックグラウンドで進むので体感への影響は小さめです。

→ [ブラウザ内蔵AIで要約する（実装ノート）](./01-built-in-ai.md)

## 2. コンテンツクレンジングが大幅に強くなった

AI に本文を送る前のノイズ除去を「クレンジング」と呼んでいます。ここが大きく変わりました。

- **プリセット4種** — 32個のトグルを `minimal`（3項目 ON）/ `balanced`（9項目 ON）/ `aggressive`（25項目 ON）/ `custom` に集約。デフォルトは `balanced` です
- **ドメイン別の上書き** — 「このサイトだけ強めに」といった調整を、既定値との差分としてサイト単位で保持できます
- **Cookie 同意バナーの除去** — OneTrust 系のバナー定型文が AI に流れていた問題に対応
- **SPA と Shadow DOM への対応** — `MutationObserver` で描画後のコンテンツ変化を拾い、`shadowRoot` や iframe の中も走査します
- **多言語パターンの拡充** — フランス語・ドイツ語・中国語の広告／SNS 定型句を追加
- **観測性** — 「何が、どの理由で除去されたか」の内訳と、クレンジング前後のペイロード差分をダッシュボードで確認できます
- **誤削除の報告ボタン** — 本文が消えすぎたときにワンクリックで報告。報告はローカルに溜まるだけで外部送信はしません

狙いは「消しすぎ」を可視化して、ユーザーが調整と報告のループを回せるようにすることです。

→ [AIに送る前の「掃除」を作り込む](./02-cleansing.md)

## 3. 閲覧履歴をアーカイブできるようになった

ローカル SQLite が肥大化してきたとき、古い履歴を安全に減らせるようになりました。`Dashboard → Archive` パネルからの2フェーズ操作です。

1. **フェーズ1（退避）** — 指定日までの履歴を標準 SQLite ファイル（`yasumaro_archive_<日付>.db`）として書き出し、ダウンロードします。この時点で本体 DB は変更されません
2. **フェーズ2（削除）** — ダウンロード後、退避済みレコードを本体から削除します。削除はフェーズ1で作ったファイルと突合せてから実行され、フェーズ1以降に追加された分は保護されます

アーカイブファイルは DB Browser for SQLite などでそのまま開ける標準形式です。あとから本体へマージ復元でき、取り込まずにパネル上で開いて検索・タイトル編集・書き戻しもできます。

→ [閲覧履歴を安全に退避する](./03-archive.md)

## 4. AI 接続テストが「本物」になった

以前の接続テストは、モデル一覧を GET するだけの疎通確認でした。API キーが推論に有効か、指定したモデル名が実在するか、本文が返るかは検証できていませんでした。

全プロバイダーで、短いプロンプトを実際に1往復させる方式に統一しました。送信先エンドポイント・送信内容・受信内容・モデル名・トークン数・HTTP ステータスを画面に表示します。空応答は成功扱いしません。複数プロバイダーを順にテストするときは、テスト中のプロバイダー名・経過時間・スピナーをリアルタイム表示します。

→ [「接続テスト、通ったのに本番で失敗する」をなくす](./04-ai-connection-test.md)

## その他の細かい前進

- OpenAI 互換（Models.dev 経由）で 70 以上の互換プロバイダー（OpenRouter、DeepSeek など）を選べる
- Ollama 宛リクエストの `Origin` ヘッダーを拡張機能側で削除。Ollama 側の CORS 設定を変えずに接続できる
- SQLite History パネルで、検索実行中は「関連度順」ソートが選べる
- ローカル Markdown 書き出しのフォーマットをテンプレート（`{{date}}` `{{title}}` `{{url}}` `{{summary}}` など）でカスタマイズできる
- 履歴一覧の各エントリに、保存時のプライバシーモード（Local Only / Full Pipeline / Masked Cloud / Cloud Only）をバッジ表示
- ツールバーバッジに「ドメインフィルターで記録対象外」を示す `∉` バッジ
- レコード保持に 365 日のデフォルト上限
- パフォーマンス最適化7件（コンテンツスクリプトの周期ポーリングを廃止、ダッシュボード履歴のクエリキャッシュ導入、PII サニタイズの ReDoS 解消など）

主なクラッシュ修正としては、SVG を含むページ（Google 検索結果、Zenn 記事など）で自動保存が落ちる問題、CNN / BBC などで「今すぐ記録」がブロックされる問題、拡張機能アップデートのたびに API キーが復号できなくなる問題、履歴が 1000 件を超えると 51 ページ目以降を開けない問題などを解消しています。

## アップグレードで気をつけること

v6.6 系からそのまま v6.8.0 に上げて問題ありません。設定の引き継ぎに影響はありません。

内蔵 AI を使う場合のみ、対応ブラウザでフラグを有効化し、初回にモデルをダウンロードする手間があります。クレンジングのプリセットは既定が `balanced` になり、以前から使っている人の 32 トグル設定はそのまま維持されます（プリセット選択欄は `custom` と表示されます）。
