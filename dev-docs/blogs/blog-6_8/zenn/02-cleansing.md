Yasumaro には、AI に本文を送る前のノイズ除去（クレンジング）があります。v6.7 系でここを大きく作り込みました。この記事はその内容です。

過去に [クレンジングの基本設計](https://zenn.dev/) を書いていますが、そこからの差分として読めます。

## 前提: 2種類のクレンジング

Yasumaro のクレンジングは2段階です。

1. **コンテンツ抽出** — Readability 系のアルゴリズムで本文らしい領域を取り出す
2. **AI 要約クレンジング** — 抽出後のテキストから、広告・ナビゲーション・SNS ボタン・定型文などをルールで削る

この記事の主題は 2 のほうです。ルールは 32 個のトグルで管理しています。

## プリセット4種

32 個のトグルを個別に調整するのは現実的ではありません。`minimal` / `balanced` / `aggressive` / `custom` の4プリセットに集約しました。

| プリセット | ON 数 | 内容 |
|---|---|---|
| `minimal` | 3 | alt テキスト、広告、ナビゲーションのみ |
| `balanced` | 9 | minimal + メタデータ、SNS、推奨記事、ポップアップ、Cookie バナー、ニュースメディア定型句 |
| `aggressive` | 25 | ほぼ全部 ON。JSON-LD 除去や遅延読み込み属性など7項目だけ OFF |
| `custom` | — | 個別調整。保存形式は 32 キーそのまま |

デフォルトは `balanced` です。

保存形式は変えていません。プリセットは「32 値を一括で埋めるショートカット」として実装しています。トグルを1つでも手で変えると、プリセット選択欄の表示は `custom` に切り替わります。

## ドメイン別の上書き

同じサイトで繰り返し誤削除が起きるとき、そのドメインだけ設定を変えられます。

実装上のポイントは2つです。

- **差分マージ** — 上書きはベース設定への差分です。指定しなかった項目はグローバル設定が使われます
- **完全一致マッチ** — ドメインは小文字化・トリム後の完全一致でのみ判定します。サブドメインは別ドメイン扱いです（`example.com` の上書きは `www.example.com` に適用されない）

サブドメインを区別する挙動は意図的です。`blog.example.com` と `shop.example.com` でページ構造が違うのはよくあることで、まとめて上書きすると片方で事故ります。

## Cookie 同意バナーの除去

OneTrust 系のライブラリ（`onetrust` / `ot-sdk` / `optanon` などのクラス名を持つ）が挿入する Cookie 同意バナーの定型文が、そのまま AI に流れていました。

`cookie` クレンジングルールを新設して対応しました。日英 12 パターン程度。`balanced` 以上のプリセットではデフォルトで有効です。

判定はクラス名の部分一致ではなくテキストマッチにしています。`cookie` を含むクラス名は正当なコンテンツにも出るため、クラス名だけで消すと誤爆します。

## SPA と Shadow DOM

静的な HTML だけを見ていると、SPA では本文が取れません。

- **SPA 対応** — `MutationObserver`（500ms デバウンス）で、描画後のコンテンツ変化を検知します
- **Shadow DOM / iframe** — `querySelectorAllDeep` 相当の再帰走査で、`shadowRoot` や iframe の中も見ます

Shadow / iframe ホストが存在しないページでは、この再帰走査の列挙を早期にゼロ化しています（v6.7.106 のパフォーマンス最適化）。大多数のページで無駄なコストを払わないためです。

## 観測性

「消しすぎ」は、見えないと直せません。

- **除去理由の内訳** — `removedByReason`（`Record<string, number>`）として、どのルールで何個の要素を消したかを記録します
- **二重ペイロード** — クレンジング前（`originalContent`）とクレンジング後を両方保持し、ダッシュボードのタブ切替で差分を確認できます

ダッシュボードの「AI 要約クレンジング」パネルでこれらを見られます。

## 誤削除の報告

本文まで消えてしまったとき、popup の「誤削除を報告」ボタンでワンクリック報告できます。

記録される内容:

- ページ URL とドメイン
- ページ HTML の先頭 500 文字
- 除去理由の統計

**この情報は `chrome.storage.local` にのみ保存され、外部へ送信されません。** 開発元への自動送信もありません。あくまでユーザー自身が調整の手がかりにするためのものです。報告キューは 50 件の FIFO です。

## なぜ可視化と報告を入れたか

クレンジングのルールは、あるサイトでうまく効いても別のサイトで本文を削ることがあります。この非対称は原理的になくせません。

そこで方針を変えました。ルールを完璧にしようとするのではなく、「何が消えたか」をユーザーが見られるようにし、消えすぎたら報告と調整でループを回せるようにする。プリセットで大枠を決め、ドメイン別上書きで個別対応し、観測性で結果を確認する、という3層です。
